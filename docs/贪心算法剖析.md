# 贪心算法剖析

> 贪心（Greedy）是最「直觉」的算法——每一步都选眼前最好的，期望最终得到全局最优。它简单、高效，但也最容易「想当然」地出错。本文从直觉到证明，全面剖析贪心算法。

## 1. 什么是贪心

### 1.1 一个生活化的比喻

你去超市买东西，要找零 41 元。收银员会怎么给你硬币（面额 1、5、10、25）？
- 拿 1 个 25 元（剩 16）
- 拿 1 个 10 元（剩 6）
- 拿 1 个 5 元（剩 1）
- 拿 1 个 1 元

每一步都选**能用的最大面额**，这就是贪心。最终用了 4 枚硬币，恰好是最少。

但贪心并非总是对。假设面额是 `{1, 3, 4}`，要找零 6：
- 贪心：4 + 1 + 1 = 3 枚
- 最优：3 + 3 = 2 枚

贪心在这里**失效**了！因为没有「贪心选择性质」。

### 1.2 形式化定义

> 贪心算法在每一步选择中都采取**当前状态下最优（最有利）的选择**，期望通过局部最优导致全局最优。

关键词是**期望**——贪心不保证全局最优，只有满足特定条件时才行。

### 1.3 贪心的核心步骤

1. **建立贪心策略**：确定「什么算当前最优」
2. **逐步选择**：每步选最优，不可撤回
3. **得到结果**：所有选择完成后即为答案

```go
func greedy(problem) Result {
    result := 初始化
    for !完成 {
        choice := 选择当前最优(problem)
        result = 应用(result, choice)
        problem = 更新(problem, choice)
    }
    return result
}
```

**注意**：贪心的选择是**不可撤回**的（区别于回溯的「撤销重来」）。一旦选了就定了。

## 2. 贪心的两个关键性质

一个问题能用贪心求最优解，必须满足：

### 2.1 贪心选择性质（Greedy Choice Property）

**通过局部最优选择能得到全局最优解**。即：每一步的最优选择，最终拼起来就是全局最优。

这是贪心可行的根本保证。并非所有问题都有此性质（如前述 `{1,3,4}` 找零）。

### 2.2 最优子结构（Optimal Substructure）

**最优解包含子问题的最优解**。即：做出贪心选择后，剩余问题仍是最优的。

这与 DP 的最优子结构相同，但贪心还额外要求「贪心选择性质」。

> ⚠️ **贪心 ⊂ DP**：贪心可以看作 DP 的特例——当 DP 的每一步最优选择唯一确定（无需比较多个子问题）时，就退化为贪心。

## 3. 贪心与 DP 的本质区别

| 维度 | 贪心 | DP |
|------|------|-----|
| 决策方式 | 每步选当前最优，不回头 | 枚举所有选择，比较后选最优 |
| 可撤回 | 否（一锤定音） | 是（记录所有状态） |
| 子问题 | 只有一个（贪心选择后的剩余） | 多个重叠子问题 |
| 时间复杂度 | 通常 O(n log n) 或 O(n) | 通常 O(n²) 或 O(n·k) |
| 正确性 | 需证明贪心选择性质 | 天然正确（穷举） |
| 风险 | 可能非最优 | 保证最优 |

### 3.1 直观对比：找零问题

**面额 `{1,5,10,25}`，找零 41**：
- 贪心：25+10+5+1 = 4 枚 ✓（恰好最优）
- DP：同样 4 枚，但需填表

**面额 `{1,3,4}`，找零 6**：
- 贪心：4+1+1 = 3 枚 ✗（非最优）
- DP：3+3 = 2 枚 ✓

**结论**：贪心快但可能错，DP 慢但保证对。能用贪心就用贪心，不行才上 DP。

## 4. 贪心算法的常见策略

### 4.1 排序后贪心

先按某维度排序，再依次贪心选择。最常见的套路。

- **区间调度**：按结束时间排序，每次选最早结束的不冲突区间
- **分配问题**：按大小排序后配对
- **分数背包**：按单位价值排序

### 4.2 优先队列贪心

用堆动态维护「当前最优」选择。

- **合并 K 个有序列表**：用最小堆每次取最小
- **任务调度**：用堆动态选最优任务

### 4.3 双指针贪心

用两个指针扫描，根据贪心策略移动。

- **盛最多水的容器**：矮的一端向内移动
- **分发糖果**：左右各扫一遍

### 4.4 模拟贪心

按规则逐步模拟，每步做最优选择。

- **跳跃游戏**：维护当前能到达的最远位置
- **买卖股票**：每次有正利润就交易

## 5. 经典例题详解

### 例题一：合并区间（0056）—— 排序贪心

> 给定区间集合，合并所有重叠区间。

**贪心策略**：按**左端点排序**，依次扫描。若当前区间左端 ≤ 上一区间右端，则重叠，合并（取右端较大）；否则不重叠，加入结果。

```go
func merge(intervals [][]int) [][]int {
    // 按左端点排序
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })

    result := [][]int{intervals[0]}
    for i := 1; i < len(intervals); i++ {
        last := result[len(result)-1]
        if intervals[i][0] <= last[1] {
            // 重叠，合并右端
            last[1] = max(last[1], intervals[i][1])
        } else {
            // 不重叠，新增
            result = append(result, intervals[i])
        }
    }
    return result
}
```

**为什么按左端排序？** 排序后，若 `intervals[i]` 与前面不重叠，则它与后面所有区间也不重叠（左端更大的必然不重叠）。

**执行过程**（`[[1,3],[2,6],[8,10],[15,18]]`）：
```
排序后: [[1,3],[2,6],[8,10],[15,18]]  （已有序）
result = [[1,3]]
i=1: [2,6], 2<=3 重叠 → 合并 [1,6]
i=2: [8,10], 8>6 不重叠 → 新增 [[1,6],[8,10]]
i=3: [15,18], 15>10 不重叠 → 新增 [[1,6],[8,10],[15,18]]
```

时间 O(n log n)（排序），空间 O(n)。

### 例题二：跳跃游戏 —— 模拟贪心

> 给定非负整数数组，每个元素表示该位置最大跳跃步数，判断能否到达最后。

**贪心策略**：维护「当前能到达的最远位置」`maxReach`。遍历每个位置，若 `i > maxReach` 则到不了；否则更新 `maxReach = max(maxReach, i + nums[i])`。

```go
func canJump(nums []int) bool {
    maxReach := 0
    for i := 0; i < len(nums); i++ {
        if i > maxReach {
            return false  // 到不了位置 i
        }
        maxReach = max(maxReach, i+nums[i])
        if maxReach >= len(nums)-1 {
            return true   // 已能到达终点
        }
    }
    return true
}
```

**为什么贪心有效？** 只要最远可达覆盖终点，必然存在一条路径（具体路径不必关心）。这是「覆盖范围」的贪心，不是「选择走哪步」的贪心。

**执行过程**（`nums = [2,3,1,1,4]`）：
```
i=0: maxReach=max(0, 0+2)=2
i=1: 1<=2, maxReach=max(2, 1+3)=4 >= 4(终点) → true
```

时间 O(n)，空间 O(1)。

### 例题三：买卖股票最佳时机 —— 简单贪心

> 给定股价数组，允许多次买卖（同时最多持一股），求最大利润。

**贪心策略**：只要今天比昨天贵，就把差价赚了。所有「上涨段」的利润之和等于最大利润。

```go
func maxProfit(prices []int) int {
    profit := 0
    for i := 1; i < len(prices); i++ {
        if prices[i] > prices[i-1] {
            profit += prices[i] - prices[i-1]  // 赚取每一段上涨
        }
    }
    return profit
}
```

**为什么有效？** 任意上涨段 `[a,b,c]`（a<b<c），分两天赚 `(b-a)+(c-b) = c-a`，与一直持有赚的一样。所以「贪心地赚每一次上涨」等价于最优。

**执行过程**（`prices = [7,1,5,3,6,4]`）：
```
i=1: 1<7, 不赚
i=2: 5>1, 赚 4, profit=4
i=3: 3<5, 不赚
i=4: 6>3, 赚 3, profit=7
i=5: 4<6, 不赚
结果: 7  （1买5卖 + 3买6卖 = 4+3）
```

时间 O(n)，空间 O(1)。

### 例题四：盛最多水的容器 —— 双指针贪心

> 给定高度数组，选两条线与 x 轴围成容器，使盛水最多。

**贪心策略**：双指针从两端向内，**移动较矮的一端**。因为面积 = min(h[l], h[r]) × 宽度，宽度在缩小，只有让 min 变大才可能增加面积。

```go
func maxArea(height []int) int {
    left, right := 0, len(height)-1
    maxWater := 0
    for left < right {
        h := min(height[left], height[right])
        maxWater = max(maxWater, h*(right-left))
        if height[left] < height[right] {
            left++
        } else {
            right--
        }
    }
    return maxWater
}
```

**为什么移动矮的而非高的？** 若移动高的一端，min 不变或更小，宽度减小 → 面积必然减小。只有移动矮端，min 才可能变大。

时间 O(n)，空间 O(1)。

### 例题五：摧毁小行星（daily/2126）—— 排序贪心

> 给定初始质量 mass 和小行星数组，按任意顺序撞击：若质量 ≥ 小行星质量则吸收（质量增加），否则被摧毁。判断能否摧毁所有。

**贪心策略**：按质量从小到大排序，依次撞击。能吸收就吸收（质量增长），遇到吸收不了的就失败。

```go
func asteroidsDestroyed(mass int, asteroids []int) bool {
    sort.Ints(asteroids)
    for _, a := range asteroids {
        if mass < a {
            return false
        }
        mass += a
    }
    return true
}
```

**为什么从小到大？** 先吸收小的能快速增大质量，为后续大的铺路。若先撞大的可能被摧毁，但小的能撞的反而没机会。贪心地「先易后难」是最优策略。

## 6. 如何证明贪心的正确性

贪心最危险的是「想当然」。证明贪心正确常用以下方法：

### 6.1 交换论证（Exchange Argument）

假设存在比贪心解更优的解，通过有限次交换把它变成贪心解且不变得更差，从而证明贪心解最优。

**示例**：区间调度按结束时间排序。
- 假设最优解 OPT 第一个区间结束比贪心解 G 的晚
- 用 G 的第一个替换 OPT 的第一个，仍不冲突且结束更早
- 逐步替换，OPT 的区间数不增 → G 不劣于 OPT

### 6.2 数学归纳法

证明：
1. 贪心的第一步是最优的
2. 若前 k 步最优，第 k+1 步也最优

### 6.3 反例法（证伪）

要证明贪心**错误**，只需找一个反例。如 `{1,3,4}` 找零 6。

### 6.4 贪心 vs 反例的思维

刷题时：
- **先找反例**：能否构造出贪心失败的案例？找不到再考虑用贪心
- **再想证明**：为什么贪心是对的？能否用交换论证说明？

## 7. 贪心失效的典型反例

### 7.1 找零问题（非标准面额）

面额 `{1,3,4}`，找零 6：
- 贪心：4+1+1=3 枚
- 最优：3+3=2 枚

### 7.2 0-1 背包

物品 `{(重量3,价值5), (重量4,价值6), (重量5,价值10)}`，容量 8：
- 按价值贪心：选 10（剩 3）→ 选不了 6 → 选 5 → 总 15
- 按性价比贪心：5/3≈1.67, 6/4=1.5, 10/5=2 → 选 10（剩3）→ 选 5 → 总 15
- 最优：选 5+6=11 重量，价值 11？不对，重算。实际最优是 6+10=16（重量9>8不行）。5+10=15（重量8）。所以这里贪心恰好对。

换个例子：`{(重量2,价值3), (重量3,价值4), (重量4,价值5)}`，容量 5：
- 贪心性价比：3/2=1.5 > 4/3≈1.33 > 5/4=1.25 → 选(2,3) 剩3 → 选(3,4) 总7
- 最优：(2,3)+(4,5)? 重量6>5不行。选(3,4)+剩余2装不下(2,3)。所以7是最优。

0-1 背包贪心通常失效，需 DP。**分数背包**（可分割）贪心才正确。

### 7.3 最长递增子序列

贪心「每次选尽可能小的下一个」看似对，但无法保证全局最长。必须 DP（`O(n²)`）或二分优化（`O(n log n)`）。

### 7.4 任务调度（有依赖）

带前后依赖的任务调度贪心往往失效，需拓扑排序 + DP。

## 8. 常见误区与避坑指南

### 8.1 想当然用贪心

最大陷阱。任何贪心策略都要先**找反例**验证。

### 8.2 排序维度选错

如区间调度，按「开始时间」排序会失效，必须按「结束时间」：
- `[[1,10],[2,3],[4,5]]` 按开始排序选 `[1,10]` 后只能选 1 个
- 按结束排序选 `[2,3],[4,5]` 共 2 个

### 8.3 混淆贪心与 DP

- 能用贪心 → 一定也能用 DP（但 DP 慢）
- 能用 DP → 不一定能用贪心（贪心可能错）
- 不确定时先用 DP 保证正确，再尝试贪心优化

### 8.4 忽略边界

- 空输入、单元素
- 全相同元素
- 逆序/顺序输入

### 8.5 贪心策略不彻底

如跳跃游戏，若只看「下一步能跳最远」而非「整体覆盖范围」，会出错。要站在全局角度定义贪心。

## 9. 如何识别一道题该用贪心

出现以下信号时，优先考虑贪心：

| 信号 | 示例 |
|------|------|
| 求**最大/最小**值 | 最大利润、最少硬币 |
| 问题可**排序后线性扫描** | 合并区间、区间调度 |
| 有「**每步选最优**」的直觉 | 跳跃游戏、盛水容器 |
| 数据规模大（n ≤ 10⁵），DP 会超时 | 多为贪心 |
| 涉及「**覆盖范围**」「**累积**」 | 跳跃游戏、加油站 |
| 分数/比率可比较 | 分数背包、性价比 |

**反信号**：
- 需要枚举所有方案 → 回溯
- 有重叠子问题且贪心可证伪 → DP
- 要求具体方案而非数值 → 多为 DP 或回溯

**验证流程**：
1. 提出贪心策略
2. **主动找反例**（花 2 分钟）
3. 找不到反例 → 尝试证明（交换论证）
4. 仍不确定 → 先写 DP 保证正确，再尝试贪心

## 结语

贪心是「**勇敢的直觉**」——它相信局部最优能导向全局最优。这种信念在很多场景下成立，但并非理所当然。

记住三句话：
1. **贪心快但可能错，DP 慢但保证对**
2. **任何贪心策略都要先找反例**
3. **排序是贪心最好的朋友——先排好序，贪心往往水到渠成**

当你能快速判断「这道题贪心行不行」，你的算法直觉就上了一个台阶。
