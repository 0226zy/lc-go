## 1. 什么是分治

### 1.1 一个生活化的比喻

想象你要在一本 1000 页的字典里查一个单词。从头翻到尾？太慢了。你会：
1. **分**：翻到中间页
2. **治**：比较中间词与目标，决定去左半还是右半
3. **合**：在选定的半本里继续这个过程

这就是分治：**把大问题切成独立的小问题，分别解决，再合并结果**。

再比如，要给 100 万个数排序：
- 一个人排太慢 → 分成两堆各 50 万
- 每堆再分……直到每堆只有 1 个数（天然有序）
- 然后两两合并有序的堆

这就是归并排序。

### 1.2 形式化定义

> 分治是一种把问题**分解为若干规模更小的独立子问题**，递归求解后**合并**子问题解的算法范式。

关键词是**独立**——子问题之间互不影响。这是分治区别于动态规划的核心（DP 的子问题重叠）。

## 2. 分治的三步范式

每个分治算法都遵循这三步：

### 第一步：分（Divide）

把原问题分解为 `k` 个规模更小的相同子问题。

- 归并排序：把数组对半切
- 快速排序：选一个 pivot，把数组分成 `< pivot` 和 `> pivot` 两部分
- 二分查找：根据中点比较结果，保留一半

### 第二步：治（Conquer）

递归求解每个子问题。当子问题足够小（基线条件）时直接求解。

- 归并排序：子数组长度为 1 时天然有序
- 快速排序：子数组长度 ≤ 1 时无需排序
- 二分查找：区间为空或命中目标时返回

### 第三步：合（Combine）

把子问题的解合并成原问题的解。

- 归并排序：合并两个有序子数组（核心工作量在此）
- 快速排序：无需合并（分区时已就位）
- 二分查找：无需合并（只递归一边，直接返回）

### 2.1 通用代码模板

```go
func divideAndConquer(problem) Result {
    if baseCase(problem) {
        return solveDirectly(problem)   // 治：基线直接求解
    }
    subProblems := divide(problem)              // 分
    results := make([]Result, len(subProblems))
    for i, sp := range subProblems {
        results[i] = divideAndConquer(sp)       // 治：递归求解
    }
    return combine(results)                     // 合
}
```

## 3. 分治与递归的关系

**分治是策略，递归是实现手段。**

- 分治描述「如何思考问题」：分成子问题、分别求解、合并
- 递归描述「如何实现代码」：函数调用自身

分治通常用递归实现，但也可用迭代（如自底向上的归并排序）。反过来，递归不一定都是分治（如阶乘递归只有单个子问题，谈不上「分」）。

| 维度 | 分治 | 递归 |
|------|------|------|
| 本质 | 算法策略 | 实现机制 |
| 子问题数量 | 通常多个（≥2） | 可单个 |
| 子问题关系 | 相互独立 | 可重叠 |
| 典型代表 | 归并排序、快速排序 | 阶乘、树遍历 |

## 4. 分治的有效性条件

一个问题能用分治，需满足：

### 4.1 可分性

问题能分解为**结构相同的**更小子问题。

- 排序：子数组排序仍是排序问题 ✓
- 最短路径：子图的最短路径不一定是全局最短 ✗（需要其他算法）

### 4.2 子问题独立性

子问题之间**互不依赖**。

- 归并排序：左半和右半独立排序，互不影响 ✓
- 最长公共子序列：`LCS(i,j)` 依赖 `LCS(i-1,j)` 和 `LCS(i,j-1)`，子问题重叠 ✗（这是 DP）

### 4.3 可合并性

子问题的解能**高效合并**成原问题的解。如果合并代价过高，分治就不划算。

- 归并排序：合并 O(n)，总 O(n log n) ✓
- 假设合并需 O(n²)：总复杂度会退化

### 4.4 规模缩减

每次分解后子问题规模必须严格缩小，否则无限递归。

## 5. 经典例题详解

### 例题一：归并排序（排序链表 0148）—— 分治的标准模板

> 给定链表头节点，将其按升序排序。要求 O(n log n) 时间。

**分治三步**：
1. **分**：用快慢指针找到链表中点，切成两半
2. **治**：递归排序左半和右半
3. **合**：合并两个有序链表

```go
func sortList(head *ListNode) *ListNode {
    // 基线：空或单节点天然有序
    if head == nil || head.Next == nil {
        return head
    }
    // 分：快慢指针找中点
    slow, fast := head, head.Next
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    mid := slow.Next
    slow.Next = nil  // 断开

    // 治：递归排序两半
    left := sortList(head)
    right := sortList(mid)

    // 合：合并两个有序链表
    return merge(left, right)
}

func merge(l1, l2 *ListNode) *ListNode {
    dummy := &ListNode{}
    cur := dummy
    for l1 != nil && l2 != nil {
        if l1.Val <= l2.Val {
            cur.Next = l1
            l1 = l1.Next
        } else {
            cur.Next = l2
            l2 = l2.Next
        }
        cur = cur.Next
    }
    if l1 != nil { cur.Next = l1 }
    if l2 != nil { cur.Next = l2 }
    return dummy.Next
}
```

**为什么找中点用快慢指针？** 快指针走 2 步，慢指针走 1 步，快指针到尾时慢指针在中点。O(n) 时间，O(1) 空间。

**执行过程**（`4→2→1→3`）：
```
sortList(4→2→1→3)
├─ 分: 中点 2，左=4→2, 右=1→3
├─ sortList(4→2)
│  ├─ 分: 中点 4, 左=4, 右=2
│  ├─ sortList(4) = 4
│  ├─ sortList(2) = 2
│  └─ merge(4, 2) = 2→4
├─ sortList(1→3)
│  ├─ 分: 中点 1, 左=1, 右=3
│  ├─ sortList(1) = 1
│  ├─ sortList(3) = 3
│  └─ merge(1, 3) = 1→3
└─ merge(2→4, 1→3) = 1→2→3→4
```

时间 O(n log n)，空间 O(log n)（递归栈）。

### 例题二：最大子数组和（0053）—— 分治的非典型应用

> 求连续子数组的最大和。

分治思路：把数组从中点分成左右两半。最大子数组和有三种可能：
1. 完全在左半
2. 完全在右半
3. **跨越中点**（左半的某个后缀 + 右半的某个前缀）

前两种递归求解，第三种需特殊处理：从中点向左扫描求最大后缀和，向右扫描求最大前缀和，两者相加。

```go
func maxSubArrayDivideConquer(nums []int, left, right int) int {
    if left == right {
        return nums[left]  // 基线：单元素
    }
    mid := (left + right) / 2

    // 情况1+2：完全在左/右
    leftMax := maxSubArrayDivideConquer(nums, left, mid)
    rightMax := maxSubArrayDivideConquer(nums, mid+1, right)

    // 情况3：跨越中点
    // 从 mid 向左求最大后缀和
    leftSum, leftBorderSum := 0, nums[mid]
    for i := mid; i >= left; i-- {
        leftSum += nums[i]
        leftBorderSum = max(leftBorderSum, leftSum)
    }
    // 从 mid+1 向右求最大前缀和
    rightSum, rightBorderSum := 0, nums[mid+1]
    for i := mid + 1; i <= right; i++ {
        rightSum += nums[i]
        rightBorderSum = max(rightBorderSum, rightSum)
    }
    crossMax := leftBorderSum + rightBorderSum

    return max(leftMax, rightMax, crossMax)
}
```

**对比**：此题最优解是 DP（Kadane 算法 O(n)），但分治解法 O(n log n) 展示了分治处理「跨越分割点」问题的通用技巧——这是分治的难点所在。

**跨越中点的处理是分治的精髓**：很多分治题的难点不在递归本身，而在如何处理「跨边界」情况。

### 例题三：合并 K 个有序链表（0023）—— 分治合并

> 合并 k 个升序链表。

**朴素思路**：两两顺序合并，`merge(merge(merge(l1,l2),l3),l4)...`。但这样总比较次数高（前面的链表被反复遍历）。

**分治思路**：把 k 个链表对半分成两组，每组递归合并成一个链表，最后合并两个结果。形成二叉树式的合并结构。

```go
func mergeKLists(lists []*ListNode) *ListNode {
    if len(lists) == 0 {
        return nil
    }
    return divideMerge(lists, 0, len(lists)-1)
}

func divideMerge(lists []*ListNode, left, right int) *ListNode {
    if left == right {
        return lists[left]  // 基线：单个链表
    }
    if left+1 == right {
        return mergeTwoLists(lists[left], lists[right])  // 两个直接合并
    }
    mid := (left + right) / 2
    l := divideMerge(lists, left, mid)
    r := divideMerge(lists, mid+1, right)
    return mergeTwoLists(l, r)
}
```

**为什么分治比顺序合并快？**
- 顺序合并：每个链表的节点被比较 O(k) 次，总 O(kN)（k 为链表数，N 为总节点数）
- 分治合并：形成 log k 层的合并树，每个节点参与 log k 次合并，总 O(N log k)

### 例题四：有序数组转二叉搜索树（0108）—— 分治构造

> 将有序数组转换为高度平衡的二叉搜索树。

**分治思路**：取数组中点作为根，左半递归构造左子树，右半递归构造右子树。天然保证平衡且符合 BST 性质。

```go
func sortedArrayToBST(nums []int) *TreeNode {
    return build(nums, 0, len(nums)-1)
}

func build(nums []int, left, right int) *TreeNode {
    if left > right {
        return nil  // 基线：区间为空
    }
    mid := (left + right) / 2
    root := &TreeNode{Val: nums[mid]}
    root.Left = build(nums, left, mid-1)    // 左半
    root.Right = build(nums, mid+1, right)  // 右半
    return root
}
```

**为什么中点作根能保证平衡？** 每次取中点，左右子数组长度差不超过 1，递归构造的子树高度差不超过 1，符合平衡 BST 定义。

### 例题五：寻找两个有序数组的中位数（0004）—— 分治的精妙

> 给定两个大小为 m 和 n 的有序数组，找出中位数。要求 O(log(m+n))。

这是分治的经典难题。O(log) 提示用二分，本质是分治：每次排除一半不可能的元素。

**核心思想**：比较两个数组的第 k/2 个元素，较小的那部分不可能包含第 k 小的元素，可以整体排除。

```go
func findMedianSortedArrays(nums1, nums2 []int) float64 {
    total := len(nums1) + len(nums2)
    if total%2 == 1 {
        return float64(findKth(nums1, nums2, total/2+1))
    }
    return float64(findKth(nums1, nums2, total/2)+findKth(nums1, nums2, total/2+1)) / 2
}

// 找两个有序数组中第 k 小的元素
func findKth(nums1, nums2 []int, k int) int {
    if len(nums1) > len(nums2) {
        return findKth(nums2, nums1, k)  // 保证 nums1 较短
    }
    if len(nums1) == 0 {
        return nums2[k-1]
    }
    if k == 1 {
        return min(nums1[0], nums2[0])
    }
    i := min(len(nums1), k/2) - 1
    j := min(len(nums2), k/2) - 1
    if nums1[i] <= nums2[j] {
        return findKth(nums1[i+1:], nums2, k-i-1)  // 排除 nums1 前 i+1 个
    }
    return findKth(nums1, nums2[j+1:], k-j-1)  // 排除 nums2 前 j+1 个
}
```

**为什么 O(log(m+n))？** 每次排除 k/2 个元素，k 从 (m+n)/2 开始，递归深度 O(log(m+n))。

## 6. 分治的复杂度分析：主定理

分治算法的复杂度通常满足递推式：
```
T(n) = a·T(n/b) + f(n)
```
其中：
- `a`：子问题个数
- `n/b`：每个子问题规模
- `f(n)`：分解与合并的代价

**主定理（Master Theorem）** 给出三种情况：

设 `c = log_b(a)`：

| 情况 | 条件 | 结论 |
|------|------|------|
| 1 | `f(n) = O(n^d)`, `d < c` | `T(n) = O(n^c)` |
| 2 | `f(n) = O(n^c)` | `T(n) = O(n^c · log n)` |
| 3 | `f(n) = O(n^d)`, `d > c` | `T(n) = O(f(n))` |

**应用示例**：
- 归并排序：`T(n) = 2T(n/2) + O(n)`，a=2, b=2, f(n)=n → 情况2，`T(n) = O(n log n)` ✓
- 二分查找：`T(n) = T(n/2) + O(1)`，a=1, b=2, f(n)=1 → 情况2，`T(n) = O(log n)` ✓
- 快速幂：`T(n) = T(n/2) + O(1)` → `T(n) = O(log n)` ✓
- Strassen 矩阵乘法：`T(n) = 7T(n/2) + O(n²)`，c=log₂7≈2.81 > 2 → 情况1，`T(n) = O(n^2.81)`

## 7. 分治的工程优化

### 7.1 切换到插入排序

归并/快排在子问题规模很小时（如 n < 16），递归开销超过排序本身。此时切换到插入排序：

```go
func mergeSort(nums []int, left, right int) {
    if right-left < 16 {
        insertionSort(nums, left, right)  // 小规模用插入排序
        return
    }
    mid := (left + right) / 2
    mergeSort(nums, left, mid)
    mergeSort(nums, mid+1, right)
    merge(nums, left, mid, right)
}
```

Go 标准库的 `sort` 包就是这样做的。

### 7.2 避免重复分配

归并排序的 merge 步骤若每次新建临时数组，会产生大量 GC 压力。可预分配一个全局辅助数组复用：

```go
var aux []int  // 全局辅助数组
func mergeSort(nums []int, left, right int) {
    // ... 使用 aux 而非每次 new
}
```

### 7.3 自底向上迭代

自顶向下的递归归并有栈开销。可改为自底向上：从长度 1 的子数组开始，两两合并，长度翻倍，直到合并整个数组。

```go
func mergeSortBottomUp(nums []int) {
    n := len(nums)
    for width := 1; width < n; width *= 2 {
        for i := 0; i < n; i += 2 * width {
            mid := min(i+width, n)
            right := min(i+2*width, n)
            merge(nums, i, mid, right)
        }
    }
}
```

无递归，空间 O(n)。

### 7.4 三路划分（快速排序优化）

当数组有大量重复元素时，普通快排会退化到 O(n²)。三路划分把数组分成 `< pivot`、`= pivot`、`> pivot` 三部分，跳过相等的部分。

## 8. 分治与其他算法的对比

| 算法 | 核心思想 | 子问题关系 | 典型应用 |
|------|---------|-----------|---------|
| 分治 | 分解→递归→合并 | 独立不重叠 | 归并排序、快速排序 |
| DP | 分解→递归→缓存 | 重叠 | 背包、LCS |
| 贪心 | 局部最优→全局最优 | 无需回溯 | 区间调度 |
| 回溯 | 枚举所有可能 | 有剪枝 | 全排列、N皇后 |

**分治 vs DP 的关键区别**：
- 分治的子问题**独立**（如归并排序左右半互不影响）
- DP 的子问题**重叠**（如斐波那契 fib(3) 被多次需要）
- 若发现分治解法有重复计算，加记忆化就变成 DP

## 9. 常见误区与避坑指南

### 9.1 子问题不独立却用分治

如最长公共子序列，`LCS(i,j)` 依赖多个重叠子状态。朴素分治会指数爆炸，必须用 DP + 记忆化。

### 9.2 合并代价过高被忽略

分治总复杂度 = 子问题复杂度之和 + 合并复杂度。若合并是 O(n²)，即使分成两半，总复杂度仍可能是 O(n²)。

### 9.3 分割不均导致退化

快速排序若每次选到最差 pivot（如已排序数组选首元素），子问题规模变为 `n-1` 和 `0`，退化到 O(n²)。解决：随机选 pivot 或三数取中。

### 9.4 忽略边界条件

- 区间 `[left, right]` 还是 `[left, right)`？
- `mid = (left+right)/2` 在 `left > right` 时会出错
- 链表找中点时，奇偶长度要统一处理

### 9.5 递归深度过大

分治通常 O(log n) 深，但最坏情况（如快排退化）可能 O(n)。对深度敏感的场景需限制或改迭代。

## 10. 如何识别一道题该用分治

出现以下信号时，优先考虑分治：

| 信号 | 示例 |
|------|------|
| 问题可**对半切**成相同结构的子问题 | 归并排序、数组转BST |
| 要求 **O(n log n)** 或 **O(log n)** | 排序、二分查找 |
| 涉及「**第 k 个**」「**中位数**」 | 快速选择、中位数 |
| 问题有「**树形**」或「**层次**」结构 | 矩阵乘法、合并K个链表 |
| 子问题明显**独立** | 多个独立子任务合并 |

**反信号**：
- 子问题重叠 → 用 DP
- 只需线性扫描 → 双指针/滑动窗口
- 需要枚举所有方案 → 回溯

## 结语

分治的智慧在于：**面对庞大复杂的问题，不要试图一口吞下，而是切分成可管理的小块，逐个击破，再汇成整体**。这不仅是一种算法，更是一种解决问题的人生哲学。

记住三句话：
1. **分、治、合——三步缺一不可**
2. **子问题必须独立，否则改用 DP**
3. **难点通常在「合」，尤其是跨边界的处理**

掌握了分治，你就拥有了归并排序、快速排序、快速选择、线段树等一众利器的思想根基。
