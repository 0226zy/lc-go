## 1. 什么是动态规划

### 1.1 一个生活化的比喻

想象你在爬楼梯（本仓库 `0070_climbing_stairs`）。每一步只能跨 1 阶或 2 阶，问爬到第 n 阶有多少种方法？

最朴素的思路是暴力枚举所有走法，但当 n=45 时，走法数以亿计，暴力根本算不完。

但如果你观察到：**「到达第 n 阶的方法数 = 到达第 n-1 阶的方法数 + 到达第 n-2 阶的方法数」**（因为最后一步要么跨 1 阶从 n-1 来，要么跨 2 阶从 n-2 来），问题瞬间变成「从小到大依次填表」，n=45 也就 45 次加法。

这就是动态规划的本质：**用空间换时间，把指数级的暴力搜索降维成多项式级的填表**。

### 1.2 形式化定义

> 动态规划是一种通过**把复杂问题分解为重叠子问题**，并**缓存子问题的解**来避免重复计算的算法范式。

关键特征是「**记住已经求过的答案**」。这与递归的分治思想不同：分治的子问题相互独立（如归并排序），而 DP 的子问题**大量重叠**（如斐波那契递归树中 `fib(3)` 被计算了很多次）。

### 1.3 从递归到 DP 的思维跨越

以斐波那契数列 `fib(n) = fib(n-1) + fib(n-2)` 为例：

```
fib(5) 的递归调用树（无记忆化）：

                fib(5)
               /      \
           fib(4)      fib(3)        ← fib(3) 被重复计算
          /     \      /     \
       fib(3) fib(2) fib(2) fib(1)   ← fib(2) 被重复计算
       /   \
    fib(2) fib(1)
```

- **朴素递归**：时间 O(2ⁿ)，`fib(3)`、`fib(2)` 被反复计算
- **记忆化搜索**：第一次算过的 `fib(k)` 存入数组，下次直接查表 —— 时间 O(n)
- **递推（标准 DP）**：从 `fib(0)`、`fib(1)` 往后算到 `fib(n)` —— 时间 O(n)

三者本质相同，只是实现角度不同：**递归 + 记忆化 = 自顶向下 DP；递推 = 自底向上 DP**。

## 2. 动态规划的两个核心要素

一个问题能用 DP 求解，必须同时满足以下两点。

### 2.1 重叠子问题（Overlapping Subproblems）

子问题在递归求解过程中被**多次重复计算**。

- 斐波那契：`fib(3)` 在求 `fib(5)` 时被算两次
- 最长公共子序列：`LCS(i,j)` 会被多个上层状态依赖

如果没有重叠，分治就够了（如快速选择），用 DP 没有意义。

### 2.2 最优子结构（Optimal Substructure）

**原问题的最优解可以由子问题的最优解构造出来**。

举例（`0300_longest_increasing_subsequence`）：
- 设 `dp[i]` = 以 `nums[i]` 结尾的最长递增子序列长度
- 若 `nums[i] > nums[j]`，则 `dp[i] = max(dp[i], dp[j] + 1)`
- 整个数组的答案 = `max(dp[i])`

「以 `nums[i]` 结尾的 LIS」的最优解，可由「以 `nums[j]` 结尾的 LIS」的最优解 +1 得到，这就是最优子结构。

> ⚠️ 注意：并非所有问题都有最优子结构。例如「最长简单路径」（不能重复经过节点）就不满足——子路径最优拼起来可能违反「简单」约束。

### 2.3 无后效性（补充但关键）

**「未来与过去无关」**：一旦状态 `dp[i]` 确定，它如何被计算出来的不影响后续决策。

- 反例：马的走法中「不能重复踩同一格」，下一步合法与否依赖历史路径 —— 不满足无后效性，需要状态压缩或搜索
- 正例：背包问题中 `dp[i][w]` 只关心「前 i 件物品、容量 w」的最大价值，不关心具体选了哪些

设计状态时，若发现「未来决策依赖历史细节」，通常需要**把历史信息编码进状态**（如状态压缩 DP）。

## 3. 两种实现方式：自顶向下 vs 自底向上

### 3.1 自顶向下（记忆化搜索 / Memoization）

```go
var memo map[int]int

func fib(n int) int {
    if n <= 1 {
        return n
    }
    if v, ok := memo[n]; ok {
        return v          // 命中缓存，直接返回
    }
    memo[n] = fib(n-1) + fib(n-2)
    return memo[n]
}
```

特点：
- **思维自然**：直接照着递推式写递归
- **只计算需要的状态**：稀疏问题时省时间
- **递归栈开销**：n 很大时可能栈溢出

### 3.2 自底向上（递推 / Tabulation）

```go
func fib(n int) int {
    if n <= 1 {
        return n
    }
    dp := make([]int, n+1)
    dp[0], dp[1] = 0, 1
    for i := 2; i <= n; i++ {
        dp[i] = dp[i-1] + dp[i-2]
    }
    return dp[n]
}
```

特点：
- **无递归开销**，通常更快
- **易于空间优化**（滚动数组、变量替换）
- **需按拓扑序遍历**，有时确定顺序较难

### 3.3 对比

| 维度 | 自顶向下（记忆化） | 自底向上（递推） |
|------|------------------|----------------|
| 实现难度 | 低（照搬递推式） | 中（需确定遍历顺序） |
| 计算量 | 仅算需要的状态 | 计算所有状态 |
| 空间 | O(状态数) + 递归栈 | O(状态数)，易优化 |
| 栈溢出 | 可能 | 无 |
| 适用场景 | 状态稀疏、思路不清时 | 大规模数据、追求常数优化 |

> 💡 **建议**：面试/刷题时先用记忆化搜索验证思路正确，再改写为递推并优化空间。

## 4. 解题五步法

遇到 DP 题，按以下五步走，思路不会乱。

### 第一步：定义状态（最难也最关键）

**`dp[...]` 代表什么？** 状态定义直接决定递推式能否成立。

常见状态定义模式：
- **以第 i 个元素结尾**：`dp[i]` = 以 `nums[i]` 结尾的最优解（如 LIS、最大子数组和）
- **前 i 个元素**：`dp[i]` = 前 i 个元素的最优解（如打家劫舍）
- **区间 `[i,j]`**：`dp[i][j]` = 区间 i~j 的最优解（如矩阵链乘、回文分割）
- **多维状态**：`dp[i][j][k]` = 前 i 项、限制 j、限制 k 时的最优解（如背包、编辑距离）

### 第二步：写出状态转移方程

问自己：**`dp[i]` 可以从哪些更小的状态转移而来？**

- 爬楼梯：`dp[i] = dp[i-1] + dp[i-2]`
- 最大子数组和：`dp[i] = max(nums[i], dp[i-1] + nums[i])`
- LIS：`dp[i] = max(dp[j] + 1)` for all `j < i` and `nums[j] < nums[i]`

### 第三步：确定初始条件与边界

- `dp[0]` 是什么？`dp[1]` 呢？
- 空数组、单元素如何处理？
- 是否需要哨兵位（如字符串 DP 从下标 1 开始以简化边界）？

### 第四步：确定计算顺序

必须保证计算 `dp[i]` 时它依赖的状态已就绪：
- 一维：通常从左到右
- 二维区间：长度从小到大（先算所有长度 1 的，再算长度 2……）
- 二维网格：行从上到下，列从左到右（或反向，取决于依赖方向）

### 第五步：返回结果

答案往往是：
- `dp[n]`（前 n 项的最优解）
- `max(dp[...])`（所有状态中的最优，如 LIS）
- `dp[m][n]`（二维终点，如编辑距离）

## 5. 动态规划的常见分类与套路

### 5.1 线性 DP

状态沿一维下标推进。代表题：

| 题目 | 状态定义 | 转移方程 |
|------|---------|---------|
| 爬楼梯 (70) | `dp[i]` = 爬到第 i 阶的方法数 | `dp[i] = dp[i-1] + dp[i-2]` |
| 最大子数组和 (53) | `dp[i]` = 以 `nums[i]` 结尾的最大和 | `dp[i] = max(nums[i], dp[i-1]+nums[i])` |
| 打家劫舍 | `dp[i]` = 前 i 间房最大收益 | `dp[i] = max(dp[i-1], dp[i-2]+nums[i])` |
| 最长递增子序列 (300) | `dp[i]` = 以 `nums[i]` 结尾的 LIS 长度 | `dp[i] = max(dp[j]+1)`, `nums[j]<nums[i]` |

### 5.2 背包 DP

**0-1 背包**：每件物品选或不选。`dp[i][w]` = 前 i 件物品、容量 w 的最大价值。转移：
```
dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])
```

**完全背包**：每件物品可选无限次。转移：
```
dp[i][w] = max(dp[i-1][w], dp[i][w-weight[i]] + value[i])  // 注意第二项是 dp[i] 不是 dp[i-1]
```

> 经典应用：零钱兑换（完全背包求组合数）、单词拆分（完全背包求能否凑出）。

### 5.3 区间 DP

状态为一段连续区间，通常 `dp[i][j]` 表示区间 `[i,j]` 的最优解。**枚举长度** 从小到大：

```
for len := 2; len <= n; len++ {
    for i := 0; i+len-1 < n; i++ {
        j := i + len - 1
        for k := i; k < j; k++ {
            dp[i][j] = op(dp[i][j], dp[i][k] + dp[k+1][j] + cost(i,j,k))
        }
    }
}
```

代表题：`0131_palindrome_partitioning`（回文分割）、戳气球、矩阵链乘。

### 5.4 状态压缩 DP

当状态中有一维是「集合」且规模很小（n ≤ 20）时，用二进制位表示集合。`dp[mask]` 表示已选元素集合为 `mask` 时的最优解。

代表题：TSP（旅行商）、小规模分配问题。

### 5.5 树形 DP

在树上做 DP，`dp[u]` 表示以节点 u 为根的子树的某种最优解，通过后序遍历合并子节点信息。

代表题：打家劫舍 III、二叉树最大路径和。

### 5.6 计数 DP

不求数值最优，而求方案数。转移时把 `max` 换成 `+`：
- 不同路径：`dp[i][j] = dp[i-1][j] + dp[i][j-1]`
- 括号生成 DP 解法（`0022`）：`dp[i] = Σ "(" + dp[j] + ")" + dp[i-1-j]`

## 6. 经典例题详解

### 例题一：爬楼梯（0070）—— DP 入门

> 每次可爬 1 或 2 阶，爬到第 n 阶有多少种方法？

**第一步：状态定义**
`dp[i]` = 爬到第 i 阶的方法数。

**第二步：转移方程**
最后一步要么从 i-1 跨 1 阶，要么从 i-2 跨 2 阶：
```
dp[i] = dp[i-1] + dp[i-2]
```

**第三步：初始条件**
`dp[0] = 1`（站在地面，1 种「不动」的方法），`dp[1] = 1`。

**第四步：计算顺序**
从小到大 `i = 2, 3, ..., n`。

**第五步：空间优化**
只依赖前两个状态，用两个变量滚动：
```go
func ClimbStairs(n int) int {
    if n <= 2 {
        return n
    }
    prev, curr := 1, 2
    for i := 3; i <= n; i++ {
        prev, curr = curr, prev+curr
    }
    return curr
}
```
时间 O(n)，空间 O(1)。

**完整推导（n=4）**：
```
dp[0]=1, dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5
```
5 种走法：`1+1+1+1`、`1+1+2`、`1+2+1`、`2+1+1`、`2+2`。✓

### 例题二：最大子数组和（0053）—— Kadane 算法

> 求连续子数组的最大和。

**关键决策点**：遍历到 `nums[i]` 时，是「延续前一段」还是「从 i 重新开始」？

**状态定义**：`dp[i]` = 以 `nums[i]` 结尾的最大子数组和。

**转移方程**：
```
dp[i] = max(nums[i], dp[i-1] + nums[i])
```
含义：要么抛弃前面（`dp[i-1]` 为负时不如从 i 重开），要么接续前段。

**初始**：`dp[0] = nums[0]`，答案初始化为 `nums[0]`。

**答案**：`max(dp[...])`，遍历时同步维护。

**空间优化**：只需上一个 `dp[i-1]`，用单变量 `curSum`：
```go
func maxSubArray(nums []int) int {
    maxSum, curSum := nums[0], 0
    for _, num := range nums {
        curSum = max(num, curSum+num)
        maxSum = max(maxSum, curSum)
    }
    return maxSum
}
```

**执行过程**（`nums = [-2,1,-3,4,-1,2,1,-5,4]`）：
```
i=0: num=-2, curSum=-2, maxSum=-2
i=1: num=1,  curSum=1,  maxSum=1     ← -2<0，抛弃前段从 1 重开
i=2: num=-3, curSum=-2, maxSum=1     ← 1>0，接续但被 -3 拖累
i=3: num=4,  curSum=4,  maxSum=4     ← -2<0，从 4 重开
i=4: num=-1, curSum=3,  maxSum=4
i=5: num=2,  curSum=5,  maxSum=5
i=6: num=1,  curSum=6,  maxSum=6     ← 峰值
i=7: num=-5, curSum=1,  maxSum=6
i=8: num=4,  curSum=5,  maxSum=6
结果：6  （子数组 [4,-1,2,1]）
```

> 💡 **思维精髓**：DP 把「在哪个位置切割」的指数级决策，转化为「每个位置只做一次二选一」的线性决策。

### 例题三：最长递增子序列（0300）—— 二维依赖

> 求最长严格递增子序列长度。

**状态定义**：`dp[i]` = 以 `nums[i]` 结尾的 LIS 长度。

**为什么定义「以 i 结尾」？** 因为递增性要求「下一个元素必须大于上一个」，必须知道子序列的最后一个元素才能判断能否接续。定义「前 i 个的 LIS」则无法保证最后一个元素是谁，无法转移。

**转移方程**：
```
dp[i] = max(dp[j] + 1)   对所有 j < i 且 nums[j] < nums[i]
```

**初始**：每个 `dp[i] = 1`（自身即长度 1 的子序列）。

**答案**：`max(dp[...])`。

**执行过程**（`nums = [10,9,2,5,3,7,101,18]`）：
```
i=0 (10): 无 j，dp[0]=1
i=1 (9) : 无 j 满足 nums[j]<9，dp[1]=1
i=2 (2) : 无，dp[2]=1
i=3 (5) : j=2 (2<5)，dp[3]=dp[2]+1=2
i=4 (3) : j=2 (2<3)，dp[4]=dp[2]+1=2
i=5 (7) : j=2,3,4 都满足，max(dp[2],dp[3],dp[4])+1=3，dp[5]=3
i=6 (101): 所有 j 都满足，max=dp[5]=3，dp[6]=4
i=7 (18): j=2,3,4,5 满足，max=dp[5]=3，dp[7]=4
答案 = max = 4  （子序列 [2,3,7,101] 或 [2,3,7,18]）
```

时间 O(n²)。**进阶**：用二分查找可优化到 O(n log n)（维护一个「最小尾元素」数组）。

### 例题四：括号生成（0022）—— 计数/枚举型 DP

> 生成 n 对括号的所有合法组合。

**核心观察**：任何合法序列第一个字符一定是 `(`，找到与之匹配的 `)`，序列被唯一分成 `(A)B` 三部分，其中 A、B 也是合法序列。

**状态定义**：`dp[i]` = 用 i 对括号生成的所有合法组合（字符串列表）。

**转移方程**：
```
dp[i] = ⋃ { "(" + a + ")" + b | j ∈ [0,i-1], a ∈ dp[j], b ∈ dp[i-1-j] }
```

**初始**：`dp[0] = [""]`。

**为什么唯一不重复？** 第一个 `(` 的匹配 `)` 位置唯一，所以 A、B 划分唯一。

详见仓库 `solutions/hot100/0022_generate_parentheses/problem.md`，内有 n=3 的完整推导。

## 7. 空间优化技巧

DP 最常见的优化是降低空间复杂度，核心思想：**只保留还需要的旧状态**。

### 7.1 滚动数组（降一维）

当 `dp[i]` 只依赖 `dp[i-1]`（和 `dp[i-2]`），不必保留整张表。

**爬楼梯**：两个变量滚动
```go
prev, curr := 1, 1
for i := 2; i <= n; i++ {
    prev, curr = curr, prev+curr
}
```

**打家劫舍**：同理，O(n) → O(1)。

### 7.2 倒序遍历（0-1 背包一维化）

0-1 背包二维 `dp[i][w]` 依赖 `dp[i-1][w]` 和 `dp[i-1][w-weight[i]]`（**上一行同列左侧**）。若压成一维 `dp[w]`，必须**倒序遍历 w**，保证 `dp[w-weight[i]]` 还是上一轮（i-1）的值：
```go
for i := 0; i < n; i++ {
    for w := W; w >= weight[i]; w-- {   // 倒序！
        dp[w] = max(dp[w], dp[w-weight[i]] + value[i])
    }
}
```
若正序遍历，`dp[w-weight[i]]` 可能已被本轮（i）更新，导致物品被重复选取——那就变成完全背包了。

### 7.3 临时变量暂存（二维依赖）

当 `dp[i][j]` 依赖 `dp[i-1][j]`、`dp[i][j-1]`、`dp[i-1][j-1]`（如编辑距离），压成一维时需用临时变量保存将被覆盖的 `dp[i-1][j-1]`：
```go
prev := 0  // 保存 dp[i-1][j-1]
for i := 1; i <= m; i++ {
    for j := 1; j <= n; j++ {
        temp := dp[j]
        dp[j] = min(dp[j]+1, dp[j-1]+1, prev+cost)
        prev = temp
    }
}
```

## 8. 常见误区与避坑指南

### 8.1 状态定义不当导致无法转移

❌ 错误：`dp[i]` = 前 i 个元素的 LIS 长度。
- 问题：不知道第 i 个元素能否接续，无法转移。

✅ 正确：`dp[i]` = **以 `nums[i]` 结尾**的 LIS 长度。

**教训**：状态必须包含「影响未来决策的全部信息」。LIS 中「最后一个元素的值」影响能否接续，必须编入状态。

### 8.2 初始条件遗漏

- 忘记 `dp[0]` 或空串情况
- 二维 DP 忘记初始化第一行/第一列
- 区间 DP 忘记 `dp[i][i]`（长度 1 区间）

### 8.3 遍历顺序错误

- 区间 DP 必须按**长度**从小到大，而不是按 i 从小到大（否则算 `dp[0][3]` 时 `dp[1][3]` 还没算）
- 0-1 背包一维化必须**倒序**
- 计数 DP 求组合数 vs 排列数，外层遍历物品还是容量决定结果

### 8.4 把贪心当 DP（或反之）

- **贪心**：每步取局部最优，不回头。要求问题有「贪心选择性质」。
- **DP**：枚举所有选择，全局最优。

例如硬币找零，若面额有 `{1,3,4}` 凑 6：
- 贪心选 4+1+1=3 枚
- 最优是 3+3=2 枚 —— 贪心失败，必须 DP。

### 8.5 状态空间爆炸

多维 DP 易超内存。如 `dp[i][j][k][l]` 每维 100 就 10⁸ 状态。此时考虑：
- 滚动数组降维
- 重新设计状态
- 改用记忆化搜索（只算可达状态）

### 8.6 整数溢出

计数 DP 结果可能极大（如组合数 C(100,50) ≈ 10²⁹），注意用 `int64` 或取模。

## 9. 如何识别一道题是否该用 DP

出现以下信号时，优先考虑 DP：

| 信号 | 示例 |
|------|------|
| 求**最优解**（最大/最小/最长/最短） | 最大子数组和、LIS |
| 求**方案数**或**是否可行** | 不同路径、单词拆分 |
| 数据规模较小（n ≤ 1000 一维，n ≤ 20 状压） | TSP |
| 问题可**分解为同类子问题** | 编辑距离 |
| 暴力解法是**指数级**且子问题重叠 | 斐波那契、背包 |
| 有「**前 i 个**」「**以 i 结尾**」「**区间**」的描述 | 打家劫舍、回文分割 |

**反信号**（通常不该用 DP）：
- 数据规模极大（n ≤ 10⁶）→ 多用贪心/二分/双指针
- 求所有具体方案（非计数）→ 回溯
- 子问题不重叠 → 分治

## 10. DP 与其他算法的对比

| 算法 | 核心思想 | 适用场景 | 与 DP 关系 |
|------|---------|---------|-----------|
| 分治 | 分解独立子问题 | 归并排序、快速排序 | DP 子问题重叠，分治不重叠 |
| 贪心 | 局部最优 → 全局最优 | 区间调度、Huffman | 贪心是 DP 的特例（无需回溯） |
| 回溯 | 枚举所有可能 | 全排列、N 皇后 | 回溯 + 记忆化 = 自顶向下 DP |
| BFS | 层层扩展求最短 | 无权图最短路 | DP 是「DAG 上的 BFS」 |
| 图论最短路 | Dijkstra/Bellman-Ford | 带权图 | 最短路本身是 DP 思想 |

**深刻联系**：DP 本质上是**在 DAG（有向无环图）上求最长/最短路**。状态是节点，转移是边，拓扑序就是计算顺序。

- **对比相似题**：如 0-1 背包 vs 完全背包，差异就在遍历顺序

动态规划的难点不在代码，而在**状态定义**与**转移方程**的构思。掌握「五步法」+「常见分类套路」，再辅以大量练习形成肌肉记忆，DP 就从玄学变成了工程。

记住三句话：
1. **重叠子问题 + 最优子结构 → 可以 DP**
2. **状态要包含影响未来的全部信息**
3. **先记忆化验证，再递推优化**
