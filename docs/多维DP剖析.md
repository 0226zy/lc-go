## 1. 什么是多维 DP

### 1.1 生活化比喻

想象你在棋盘上从左上角走到右下角，每格有一个金币，只能向右或向下走，求能捡到的最大金币数。

你站在 `(i,j)` 时，未来能捡多少取决于「当前在哪」和「之后怎么走」。只用一个数 `i`（行）无法描述位置，必须用 `(i,j)` 两个数——这就是**二维 DP**。

推广到三维、四维，就是多维 DP。

### 1.2 形式化定义

> 多维 DP 是指状态由**两个或更多维度**共同决定的动态规划，形如 `dp[i][j]`、`dp[i][j][k]`。

每一维通常代表：
- 一个序列的位置
- 一个限制量（容量、长度、次数）
- 一个坐标（网格行列）

## 2. 为什么要多维：信息完整性原则

DP 状态设计的第一原则：**状态必须包含影响未来决策的全部信息**。

### 2.1 反例：一维不够

「编辑距离」：把字符串 A 变成 B 的最少操作数。
- 若只定义 `dp[i]` = A 的前 i 个字符变成 B 的最少操作 —— **无法转移**，因为不知道 B 处理到哪了
- 必须定义 `dp[i][j]` = A 的前 i 个字符变成 B 的前 j 个字符的最少操作

### 2.2 维度的本质

每多一维，本质上是多记录一个「影响未来的变量」。维度数 = 影响未来的独立变量数。

> ⚠️ 维度并非越多越好。每多一维，状态数乘以该维规模，容易超时/超内存。能用低维解决的绝不高维。

## 3. 常见的多维维度组合

| 维度组合 | 典型题目 |
|---------|---------|
| `[i][j]` 双序列 | 编辑距离、最长公共子序列 |
| `[i][j]` 网格 | 最小路径和、不同路径 |
| `[i][j]` 区间 | 戳气球、回文分割 |
| `[i][j][k]` 带限制 | 限制次数的买卖股票、三维背包 |
| `[i][j][flag]` 带状态 | 含「是否持有」「是否匹配通配符」等 |

## 4. 经典例题详解

### 例题一：最小路径和（网格二维 DP）

> 给定 `m×n` 网格，每格有非负数，从左上走到右下（只能右或下），求路径最小和。

**状态定义**：`dp[i][j]` = 从 `(0,0)` 到 `(i,j)` 的最小路径和。

**转移**：
```
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```
来自上方或左方，取较小。

**初始**：`dp[0][0] = grid[0][0]`；第一行只能从左来，第一列只能从上来。

**执行过程**（grid = `[[1,3,1],[1,5,1],[4,2,1]]`）：
```
dp[0][0]=1, dp[0][1]=4, dp[0][2]=5       (第一行累加)
dp[1][0]=2, dp[1][1]=min(4,2)+5=7, dp[1][2]=min(5,7)+1=6
dp[2][0]=6, dp[2][1]=min(7,6)+2=8, dp[2][2]=min(6,8)+1=7
结果: 7
```

时间 O(mn)，空间 O(mn)，可优化为 O(n)。

---

### 例题二：不同路径（计数型二维 DP）

> 从 `m×n` 网格左上走到右下，只能右或下，问有多少种走法。

**状态**：`dp[i][j]` = 到达 `(i,j)` 的路径数。

**转移**：`dp[i][j] = dp[i-1][j] + dp[i][j-1]`（来自上和左的路径数之和）。

**初始**：第一行和第一列全为 1（只有一种走法）。

**数学本质**：答案 = C(m+n-2, m-1)（组合数）。

---

### 例题三：编辑距离（双序列二维 DP）

> 把 A 变成 B 的最少操作（插入/删除/替换单个字符）。

**状态**：`dp[i][j]` = A 前 i 字符变成 B 前 j 字符的最少操作。

**转移**（考虑 A[i-1] 与 B[j-1]）：
```
若 A[i-1] == B[j-1]: dp[i][j] = dp[i-1][j-1]           (无需操作)
否则: dp[i][j] = 1 + min(
    dp[i-1][j-1],   // 替换
    dp[i-1][j],     // 删除 A[i-1]
    dp[i][j-1]      // 插入 B[j-1] 到 A
)
```

**执行过程**（A="horse", B="ros"）：
```
    ""  r  o  s
""   0  1  2  3
h    1  1  2  3
o    2  2  1  2
r    3  2  2  2
s    4  3  3  2
e    5  4  4  3
结果: 3 (horse→rorse→rose→ros)
```

### 例题四：买卖股票含冷冻期（二维 + 状态机）

> 可多次买卖，但卖出后第二天不能买（冷冻期），求最大利润。

一维不够，因为「今天能否买」依赖「昨天是否卖」。需用状态机：

- `dp[i][0]` = 第 i 天持有股票的最大利润
- `dp[i][1]` = 第 i 天不持有且处于冷冻期的最大利润
- `dp[i][2]` = 第 i 天不持有且非冷冻期的最大利润

**转移**：
```
dp[i][0] = max(dp[i-1][0], dp[i-1][2] - price[i])  // 继续持有 或 今天买入(需非冷冻)
dp[i][1] = dp[i-1][0] + price[i]                    // 今天卖出
dp[i][2] = max(dp[i-1][1], dp[i-1][2])              // 不操作，从冷冻或非冷冻来
```

这是「带状态标志位的多维 DP」，flag 维度记录离散状态。

---

### 例题五：正则表达式匹配（二维 + 通配状态）

> `.` 匹配任意单字符，`*` 匹配前一个字符 0 次或多次。

**状态**：`dp[i][j]` = s 前 i 字符是否匹配 p 前 j 字符。

**转移**（核心在 `*`）：
```
若 p[j-1] == '*':
    dp[i][j] = dp[i][j-2]  // * 匹配 0 次（删除前一个字符+*）
            || (dp[i-1][j] && (s[i-1]==p[j-2] || p[j-2]=='.'))  // * 匹配多次
否则:
    dp[i][j] = dp[i-1][j-1] && (s[i-1]==p[j-1] || p[j-1]=='.')
```

`*` 的处理是难点：要么让它「不起作用」（匹配 0 次），要么让它「再吃一个字符」（匹配多次，依赖 `dp[i-1][j]`）。

## 5. 多维 DP 的遍历顺序

### 5.1 通用原则

**计算 `dp[i][j]` 时，它依赖的状态必须已就绪。**

- 网格/双序列：`i` 从小到大，`j` 从小到大
- 区间：按**长度**从小到大（先算所有长度 1，再长度 2……）
- 带状态机：通常按 `i` 从小到大，状态维度无所谓顺序

### 5.2 区间 DP 的遍历

```go
for length := 2; length <= n; length++ {       // 枚举区间长度
    for i := 0; i+length-1 < n; i++ {          // 枚举左端点
        j := i + length - 1                    // 右端点
        for k := i; k < j; k++ {               // 枚举分割点
            dp[i][j] = op(dp[i][j], dp[i][k] + dp[k+1][j] + cost)
        }
    }
}
```

### 5.3 倒序遍历（背包降维时）

0-1 背包一维化时，容量维度必须**倒序**，保证 `dp[w-weight]` 是上一轮的值。

## 6. 空间优化：降维打击

### 6.1 滚动数组（降一维）

当 `dp[i][j]` 只依赖 `dp[i-1][...]`，可只保留两行交替使用：

```go
// 原始 O(mn) 空间
dp := make([][]int, m)  // m 行

// 优化 O(n) 空间
prev := make([]int, n)
curr := make([]int, n)
```

### 6.2 单数组原地更新

若 `dp[i][j]` 只依赖 `dp[i-1][j]` 和 `dp[i][j-1]`（如最小路径和），可压成一维：

```go
dp := make([]int, n)
for i := 0; i < m; i++ {
    for j := 0; j < n; j++ {
        if i == 0 && j == 0 {
            dp[0] = grid[0][0]
        } else if i == 0 {
            dp[j] = dp[j-1] + grid[i][j]      // 只从左来
        } else if j == 0 {
            dp[0] = dp[0] + grid[i][0]        // 只从上来
        } else {
            dp[j] = min(dp[j], dp[j-1]) + grid[i][j]  // dp[j]是上方旧值, dp[j-1]是左侧新值
        }
    }
}
```

### 6.3 临时变量保存被覆盖值

当依赖 `dp[i-1][j-1]`（左上对角），压成一维时 `dp[j-1]` 会被覆盖，需用临时变量暂存：

```go
prev := 0  // 保存 dp[i-1][j-1]
for j := 1; j <= n; j++ {
    temp := dp[j]
    dp[j] = ... // 用 prev 计算
    prev = temp
}
```

## 7. 常见误区与避坑

### 7.1 维度不足导致无法转移

如编辑距离只用一维 —— 无法知道 B 处理到哪。**宁可先多加维度保证正确，再考虑能否降维。**

### 7.2 维度过高导致超时

`dp[i][j][k][l]` 每维 100 就 10⁸ 状态。此时考虑：
- 重新设计状态减少维度
- 改用记忆化搜索只算可达状态
- 寻找单调性优化

### 7.3 边界初始化遗漏

- 第一行、第一列单独处理
- 空串/空序列的 `dp[0][j]`、`dp[i][0]`
- 区间 DP 的 `dp[i][i]`（长度 1）

### 7.4 遍历顺序错误

区间 DP 按长度而非按 i —— 否则算 `dp[0][3]` 时 `dp[1][3]` 还没算。

### 7.5 数组开小了

`dp[i][j]` 中 i、j 若表示「前 i 个」，数组要开 `n+1` 以容纳空串情况。

## 8. 识别信号

出现以下信号时，考虑多维 DP：

| 信号 | 示例 |
|------|------|
| 涉及**两个序列**对比 | 编辑距离、LCS |
| **网格/棋盘**上的路径 | 最小路径和、不同路径 |
| 有**多个限制条件** | 限制交易次数的股票 |
| 状态有**离散标志位** | 是否持有、是否匹配 |
| 问题需**区间分割** | 戳气球、矩阵链乘 |

**反信号**：
- 单序列单限制 → 一维 DP
- 子问题不重叠 → 分治
- 只需贪心选择 → 贪心

---

## 结语

多维 DP 的核心是**信息完整性**：状态必须记录所有影响未来的变量。设计状态时，问自己「未来决策还依赖什么？」把每个依赖都编入维度。

记住三句话：
1. **状态要包含影响未来的全部信息——缺了就加维度**
2. **先保证正确再加维度，再考虑能否降维优化**
3. **遍历顺序由依赖关系决定——区间按长度，网格按行列**
