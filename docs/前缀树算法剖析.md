# 前缀树算法剖析

> Trie（发音 "try"），又称前缀树或字典树，是一种专门处理**字符串前缀匹配**的树形数据结构。搜索引擎自动补全、输入法联想、拼写检查……这些功能背后都有 Trie 的身影。它把"共享前缀"这一特性发挥到极致，让查找、插入、前缀匹配都能在 O(L) 时间内完成。

## 1. 什么是前缀树

### 1.1 一个生活化的比喻

你在手机输入法里打"hel"，输入法立刻联想出 "hello"、"help"、"hell"……它是怎么做到的？

如果用哈希表存所有单词，要找以 "hel" 开头的词，只能遍历整个哈希表逐个检查——太慢了。

**Trie 的做法**：把所有单词按字符逐层展开成一棵树，**共享相同前缀的单词走同一条路径**。找 "hel" 开头的词，只需沿着 h→e→l 走三步，然后收集这棵子树下的所有单词即可。

### 1.2 形式化定义

> Trie 是一棵多叉树，每条边代表一个字符。从根到某节点的路径拼接起来，就是一个字符串的**前缀**。用 `isEnd` 标记节点是否为完整单词的结尾。

### 1.3 直观图示

插入 `"apple"`, `"app"`, `"bat"` 后的 Trie 结构：

```
            root
           /    \
          a      b
         /        \
        p          a
       /            \
      p              t*
     / \
    l   (isEnd=true)  ← "app" 在此结束
   /
  e
 /
(isEnd=true)           ← "apple" 在此结束
```

**关键观察**：
- `"app"` 和 `"apple"` 共享 `a→p→p` 前缀，只存了一份
- `isEnd` 标记区分"前缀"和"完整单词"：`app` 是完整词，`ap` 只是前缀

### 1.4 为什么用 Trie

| 优势 | 说明 |
|------|------|
| **前缀共享** | 相同前缀只存一次，节省空间 |
| **查找高效** | O(L)，L 是字符串长度，与存储总量无关 |
| **前缀匹配** | 天然支持"以 X 开头的所有词"查询 |
| **有序性** | 按字典序遍历即得到排序结果 |

## 2. Trie 的结构定义

### 2.1 标准实现（数组存子节点）

```go
type Trie struct {
    children [26]*Trie // 26 个小写字母
    isEnd    bool      // 是否为完整单词的结尾
}
```

- `children[0]` 对应 `'a'`，`children[1]` 对应 `'b'`，以此类推
- `isEnd = true` 表示从根到该节点的路径是一个完整单词

**为什么用数组？** 查找子节点 O(1)，`children[c - 'a']` 直接定位。

### 2.2 空间分析

- 每个节点固定 26 个指针（小写字母场景）
- 插入 N 个平均长度 L 的单词，最坏 O(N·L) 个节点
- 每个节点 26 指针 = 208 字节（64 位系统），空间开销较大

### 2.3 哈希表优化版

```go
type Trie struct {
    children map[byte]*Trie // 按需分配，稀疏存储
    isEnd    bool
}
```

- 只存实际存在的子节点，节省空间
- 查找 O(1) 均摊，但常数因子比数组大
- 适合字符集较大（如 Unicode）或稀疏场景

## 3. 核心操作详解

### 3.1 插入 Insert

**思路**：从根出发，逐个字符向下走，走不通就创建新节点，最后标记 `isEnd`。

```
插入 "apple"：
  root → a(新建) → p(新建) → p(新建) → l(新建) → e(新建, isEnd=true)
```

```go
func (t *Trie) Insert(word string) {
    node := t
    for i := 0; i < len(word); i++ {
        idx := word[i] - 'a'
        if node.children[idx] == nil {
            node.children[idx] = &Trie{}
        }
        node = node.children[idx]
    }
    node.isEnd = true // 标记单词结尾
}
```

**复杂度**：时间 O(L)，空间 O(L)（最坏全新建节点）。

### 3.2 查找 Search

**思路**：从根出发逐字符走，走不通返回 false；走完了检查 `isEnd`。

```go
func (t *Trie) Search(word string) bool {
    node := t
    for i := 0; i < len(word); i++ {
        idx := word[i] - 'a'
        if node.children[idx] == nil {
            return false // 走不通，单词不存在
        }
        node = node.children[idx]
    }
    return node.isEnd // 关键：检查是否为完整单词
}
```

**关键点**：走完不代表找到了！`"app"` 走完路径后如果 `isEnd=false`，说明只插入过 `"apple"`，`"app"` 不是完整词。

**复杂度**：时间 O(L)。

### 3.3 前缀匹配 StartsWith

**思路**：和 Search 几乎一样，但**不检查 `isEnd`**——只要路径存在就是前缀。

```go
func (t *Trie) StartsWith(prefix string) bool {
    node := t
    for i := 0; i < len(prefix); i++ {
        idx := prefix[i] - 'a'
        if node.children[idx] == nil {
            return false
        }
        node = node.children[idx]
    }
    return true // 不检查 isEnd！只要能走完就是前缀
}
```

**Search vs StartsWith 的区别**：

| 操作 | 走完路径后 | 含义 |
|------|----------|------|
| Search | 检查 `isEnd` | 这个词是否被完整插入过 |
| StartsWith | 不检查 | 是否有以该前缀开头的词 |

### 3.4 公共子过程：定位前缀节点

三个操作的前半段逻辑相同——"沿着字符走"。可以抽取公共方法：

```go
// 从根出发沿 prefix 走，返回终点节点；走不通返回 nil
func (t *Trie) seek(prefix string) *Trie {
    node := t
    for i := 0; i < len(prefix); i++ {
        idx := prefix[i] - 'a'
        if node.children[idx] == nil {
            return nil
        }
        node = node.children[idx]
    }
    return node
}

func (t *Trie) Search(word string) bool {
    node := t.seek(word)
    return node != nil && node.isEnd
}

func (t *Trie) StartsWith(prefix string) bool {
    return t.seek(prefix) != nil
}
```

## 4. Trie vs 哈希表 vs 排序数组

| 维度 | Trie | 哈希表 | 排序数组 |
|------|------|--------|---------|
| 精确查找 | O(L) | O(L) 均摊 | O(L log N) 二分 |
| 前缀匹配 | O(L) | ❌ 不支持 | O(L log N) 二分定位 |
| 空间 | O(N·L) 共享前缀更省 | O(N·L) | O(N·L) |
| 有序遍历 | ✅ 字典序 | ❌ 无序 | ✅ 已排序 |
| 最长前缀 | O(L) | ❌ 不支持 | O(L log N) |
| 实现复杂度 | 中等 | 简单 | 简单 |

**结论**：需要前缀匹配 → Trie；只需精确查找 → 哈希表；需要有序且少修改 → 排序数组。

## 5. 经典例题详解

### 5.1 实现 Trie (LeetCode 208)

最基础的 Trie 实现，见上文核心操作。

```go
type Trie struct {
    children [26]*Trie
    isEnd    bool
}

func Constructor() Trie {
    return Trie{}
}

func (t *Trie) Insert(word string) {
    node := t
    for i := 0; i < len(word); i++ {
        idx := word[i] - 'a'
        if node.children[idx] == nil {
            node.children[idx] = &Trie{}
        }
        node = node.children[idx]
    }
    node.isEnd = true
}

func (t *Trie) Search(word string) bool {
    node := t
    for i := 0; i < len(word); i++ {
        idx := word[i] - 'a'
        if node.children[idx] == nil {
            return false
        }
        node = node.children[idx]
    }
    return node.isEnd
}

func (t *Trie) StartsWith(prefix string) bool {
    node := t
    for i := 0; i < len(prefix); i++ {
        idx := prefix[i] - 'a'
        if node.children[idx] == nil {
            return false
        }
        node = node.children[idx]
    }
    return true
}
```

### 5.2 搜索单词（含通配符）(LeetCode 211)

**问题**：支持 `.` 匹配任意字母。

**思路**：遇到 `.` 时递归所有子节点。

```go
func (t *WordDictionary) Search(word string) bool {
    var dfs func(node *WordDictionary, idx int) bool
    dfs = func(node *WordDictionary, idx int) bool {
        if idx == len(word) {
            return node.isEnd
        }
        ch := word[idx]
        if ch == '.' {
            // 通配符：尝试所有子节点
            for _, child := range node.children {
                if child != nil && dfs(child, idx+1) {
                    return true
                }
            }
            return false
        }
        // 普通字母：精确匹配
        child := node.children[ch-'a']
        if child == nil {
            return false
        }
        return dfs(child, idx+1)
    }
    return dfs(t, 0)
}
```

**复杂度**：无通配符 O(L)；有通配符最坏 O(26^L)。

### 5.3 单词搜索 II (LeetCode 212)

**问题**：在网格中找出所有字典中的单词。

**思路**：把 words 建成 Trie，然后在网格上 DFS，**用 Trie 剪枝**——当前路径不是任何单词前缀就停止。

```go
func findWords(board [][]byte, words []string) []string {
    // 1. 建 Trie
    root := &TrieNode{}
    for _, w := range words {
        insert(root, w)
    }

    // 2. 网格 DFS + Trie 剪枝
    m, n := len(board), len(board[0])
    result := []string{}

    var dfs func(i, j int, node *TrieNode, path []byte)
    dfs = func(i, j int, node *TrieNode, path []byte) {
        if i < 0 || i >= m || j < 0 || j >= n || board[i][j] == '#' {
            return
        }
        ch := board[i][j]
        child := node.children[ch-'a']
        if child == nil {
            return // 剪枝：不是任何单词的前缀
        }

        path = append(path, ch)
        if child.isEnd {
            result = append(result, string(path))
            child.isEnd = false // 去重：找到后标记，避免重复
        }

        board[i][j] = '#' // 标记已访问
        dfs(i-1, j, child, path)
        dfs(i+1, j, child, path)
        dfs(i, j-1, child, path)
        dfs(i, j+1, child, path)
        board[i][j] = ch // 回溯
    }

    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            dfs(i, j, root, []byte{})
        }
    }
    return result
}
```

**关键点**：Trie 在此充当"剪枝指南"——只有当前路径是某单词前缀时才继续深搜。

### 5.4 键值映射 (LeetCode 677)

**问题**：Trie 节点存值，支持"求所有以 prefix 开头的单词值之和"。

**思路**：Trie + DFS 收集子树。

```go
type MapSum struct {
    children [26]*MapSum
    val      int
    isEnd    bool
}

func (m *MapSum) Sum(prefix string) int {
    node := m
    for i := 0; i < len(prefix); i++ {
        idx := prefix[i] - 'a'
        if node.children[idx] == nil {
            return 0
        }
        node = node.children[idx]
    }
    // DFS 收集子树所有值
    var dfs func(n *MapSum) int
    dfs = func(n *MapSum) int {
        sum := 0
        if n.isEnd {
            sum += n.val
        }
        for _, child := range n.children {
            if child != nil {
                sum += dfs(child)
            }
        }
        return sum
    }
    return dfs(node)
}
```

**优化**：每个节点维护 `sum` 字段，插入时沿路径累加，Sum 操作 O(L)。

## 6. Trie 的变体与优化

### 6.1 压缩 Trie (Radix Tree / Patricia Trie)

将单字符路径合并为字符串路径，减少节点数：

```
标准 Trie:    root → a → p → p → l → e
压缩 Trie:    root → "apple"
```

适合前缀重复度低的场景，节省空间但实现更复杂。

### 6.2 后缀自动机 / 后缀树

将字符串的所有后缀插入 Trie，用于子串匹配。构建复杂，但能解决很多字符串问题。

### 6.3 双数组 Trie

用两个数组（base 和 check）压缩存储，空间效率高，常用于中文分词等工业场景。

### 6.4 节点存值

标准 Trie 只存"有没有"，可以在节点上额外存信息：
- `val int`：键值映射
- `count int`：经过该节点的单词数（前缀计数）
- `index int`：单词在原数组中的下标

## 7. 常见误区与避坑指南

### 7.1 忘记检查 isEnd

```go
// ❌ 错误：走完路径就返回 true
func (t *Trie) Search(word string) bool {
    node := t.seek(word)
    return node != nil  // "app" 可能只是 "apple" 的前缀！
}

// ✅ 正确：检查 isEnd
func (t *Trie) Search(word string) bool {
    node := t.seek(word)
    return node != nil && node.isEnd
}
```

### 7.2 字符索引越界

```go
// ❌ 错误：没减 'a'，直接用字符值
idx := word[i]          // 'a' = 97，数组越界！

// ✅ 正确：减去基准
idx := word[i] - 'a'    // 'a' = 0, 'b' = 1, ...
```

### 7.3 大小写未处理

```go
// ❌ 错误：输入可能含大写
idx := word[i] - 'a'  // 'A' - 'a' = -32，负数越界！

// ✅ 正确：统一转小写
idx := strings.ToLower(string(word[i]))[0] - 'a'
```

### 7.4 Search 和 StartsWith 混淆

```go
// Search：完整单词，检查 isEnd
// StartsWith：前缀，不检查 isEnd
```

两者代码几乎一样，差别就在最后一行 `node.isEnd`。这是面试中最常被问到的区别。

### 7.5 通配符搜索未剪枝

```go
// ❌ 错误：遇到 '.' 遍历所有 26 个字母
for c := 'a'; c <= 'z'; c++ {
    // 即使 children[c-'a'] == nil 也尝试
}

// ✅ 正确：只遍历存在的子节点
for _, child := range node.children {
    if child != nil && dfs(child, idx+1) {
        return true
    }
}
```

## 8. 如何识别一道题该用 Trie

### 8.1 信号清单

| 信号 | 暗示 Trie |
|------|----------|
| "前缀匹配" / "以 X 开头" | ✅ 核心场景 |
| "自动补全" / "联想" | ✅ 经典应用 |
| "字典" / "词典" 查找 | ✅ |
| 多个字符串 + 公共前缀 | ✅ 空间优势 |
| 网格搜索 + 单词列表 | ✅ Trie 剪枝 |
| 通配符匹配 `.` | ✅ Trie + DFS |
| "最长公共前缀" | ⚠️ 可能，但排序+遍历更简单 |
| 精确查找单个字符串 | ❌ 哈希表更好 |

### 8.2 判定流程

```
题目涉及字符串集合？
  ├─ 需要前缀匹配 → Trie
  ├─ 需要通配符 → Trie + DFS
  ├─ 网格搜索单词列表 → Trie 剪枝
  ├─ 键值前缀求和 → Trie + 节点存值
  └─ 只需精确查找 → 哈希表
```

> **总结**：Trie 的精髓在于"**共享前缀**"——把字符串按字符逐层展开成一棵树，相同前缀只存一份。掌握三个核心操作（Insert / Search / StartsWith）和 `isEnd` 标记，就能解决绝大多数 Trie 题目。记住：**插入走到底标记 isEnd，查找走到底检查 isEnd，前缀匹配走到底就返回 true**。
