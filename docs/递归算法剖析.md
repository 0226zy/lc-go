## 1. 什么是递归

### 1.1 一个生活化的比喻

想象你站在一队人里，想知道自己排第几。你不知道前面有多少人，但你可以问前面的人：「你排第几？」他也不知道，于是他再问前面的人……直到问到队首的人，他知道自己排第 1，于是回答「1」；这个答案一层层传回来，每个人都 +1，最后你就知道了自己的位置。

这就是递归：
- **递**：把问题「向下传递」给更小规模的同类问题
- **归」：从最小规模问题的答案「回传」组合出原问题的答案

### 1.2 形式化定义

> 递归是一个函数**直接或间接调用自身**的机制，通过把问题分解为**结构相同但规模更小**的子问题来求解。

关键特征：**问题本身与子问题具有相同结构**（self-similar）。

### 1.3 最经典的例子：阶乘

```go
func factorial(n int) int {
    if n <= 1 {
        return 1           // 基线条件
    }
    return n * factorial(n-1)  // 递归调用
}
```

`factorial(5)` 的展开：
```
factorial(5)
= 5 * factorial(4)
= 5 * (4 * factorial(3))
= 5 * (4 * (3 * factorial(2)))
= 5 * (4 * (3 * (2 * factorial(1))))
= 5 * (4 * (3 * (2 * 1)))     ← 触底，开始「归」
= 5 * (4 * (3 * 2))
= 5 * (4 * 6)
= 5 * 24
= 120
```

## 2. 递归的三要素

写好一个递归，必须想清楚三件事。

### 2.1 基线条件（Base Case）—— 何时停止

**没有基线条件的递归会无限循环，最终栈溢出。**

```go
func bad(n int) int {
    return bad(n - 1)  // 永远停不下来！
}
```

基线条件是递归的「锚点」，是问题规模最小、可以直接给出答案的情形。

- 阶乘：`n <= 1` 时返回 1
- 链表：`head == nil` 时返回 nil
- 二叉树：`root == nil` 时返回

### 2.2 递归关系（Recursive Step）—— 如何缩小规模

每次递归调用必须让问题**严格向基线条件靠近**，否则永远到不了终点。

- 阶乘：`n → n-1`（每次减 1，必然到达 1）
- 链表：`head → head.Next`（每次后移一位，必然到达 nil）
- 二叉树：`root → root.Left / root.Right`（每次进入子树，必然到达空节点）

### 2.3 结果组合（Combine）—— 如何由子答案构造原答案

这是递归的「灵魂」——如何把子问题的解拼成原问题的解。

- 阶乘：`n * factorial(n-1)`（乘法组合）
- 树的最大深度：`1 + max(depth(left), depth(right))`（取大 +1）
- 反转链表：把 `head.Next` 反转后，把 head 接到末尾

## 3. 递归的执行过程：调用栈

理解递归的关键，是理解**调用栈**（Call Stack）。

### 3.1 调用栈的工作原理

每次函数调用，系统都会在栈上压入一帧（frame），保存局部变量、参数、返回地址。函数返回时弹出该帧。

```
调用 factorial(5) 时的栈变化：

压栈阶段（递）：
┌─────────────┐
│ factorial(1) │ ← 栈顶，即将返回
├─────────────┤
│ factorial(2) │
├─────────────┤
│ factorial(3) │
├─────────────┤
│ factorial(4) │
├─────────────┤
│ factorial(5) │ ← 栈底
└─────────────┘

弹栈阶段（归）：
factorial(1) 返回 1 → 弹出
factorial(2) 计算 2*1=2 返回 → 弹出
factorial(3) 计算 3*2=6 返回 → 弹出
factorial(4) 计算 4*6=24 返回 → 弹出
factorial(5) 计算 5*24=120 返回 → 弹出
栈空，程序结束
```

### 3.2 为什么会栈溢出

栈大小有限（Go 默认 1GB，但每帧有开销；其他语言如 Python 默认 1000 层）。递归深度过大就会 `stack overflow`。

```go
// 递归求斐波那契，n=50 时计算量爆炸（非栈溢出，是时间爆炸）
func fib(n int) int {
    if n <= 1 { return n }
    return fib(n-1) + fib(n-2)  // fib(3) 被重复计算多次
}
```

## 4. 递归思维：自顶向下 vs 自底向上

递归有两种思考方向，理解它们的区别能帮你更灵活地解题。

### 4.1 自顶向下（Top-Down）

**从原问题出发，向下递归到基线，回溯时组合答案。** 也就是「标准递归」。

```
问题(n) → 子问题(n-1) → ... → 基线 → 回溯组合
```

特点：
- 思维自然，直接照搬递推式
- 可能重复计算（如朴素斐波那契）
- 加记忆化后即「自顶向下 DP」

### 4.2 自底向上（Bottom-Up）

**从基线出发，逐步向上构造到原问题。** 通常用循环实现，即「递推」。

```
基线 → 子问题(小) → ... → 原问题(大)
```

特点：
- 无递归栈开销
- 天然避免重复计算
- 即「自底向上 DP」

### 4.3 对比示例：树的最大深度

**自顶向下（递归）**：
```go
func maxDepth(root *TreeNode) int {
    if root == nil {
        return 0
    }
    return 1 + max(maxDepth(root.Left), maxDepth(root.Right))
}
```

**自底向上（思路）**：先算左右子树深度，再 +1。其实上面的递归本身就是自底向上回溯的——叶子返回 0，父节点取 `max+1`。

> 💡 树的问题大多是「自底向上」回溯型递归：先递归子树，再用子树结果组合当前节点答案。

## 5. 经典应用场景

递归在以下场景中大放异彩：

| 场景 | 示例 | 递归结构 |
|------|------|---------|
| **树形结构** | 二叉树遍历、深度、翻转 | `左子树 + 右子树 + 当前` |
| **链表操作** | 反转、合并、交换 | `head + 递归(rest)` |
| **分治问题** | 归并排序、快速排序 | `合并(递归(左半), 递归(右半))` |
| **回溯搜索** | 全排列、子集、N皇后 | `选/不选 → 递归下一层 → 撤销` |
| **数学定义** | 阶乘、斐波那契、组合数 | 直接照搬数学递推式 |
| **字符串解析** | 括号匹配、表达式求值 | 递归处理嵌套结构 |

**为什么树和链表特别适合递归？** 因为它们本身就是**递归定义的数据结构**：
- 链表 = 节点 + 更短的链表
- 二叉树 = 节点 + 左子树 + 右子树

数据结构是递归的，操作自然也用递归。

## 6. 经典例题详解

### 例题一：二叉树的最大深度（0104）—— 递归入门

> 给定二叉树，求其最大深度。

**递归三要素**：
- 基线：`root == nil` → 深度 0
- 缩小规模：进入左右子树
- 组合：`1 + max(左子树深度, 右子树深度)`

```go
func maxDepth(root *TreeNode) int {
    if root == nil {
        return 0
    }
    return 1 + max(maxDepth(root.Left), maxDepth(root.Right))
}
```

**执行过程示例**：
```
        3
       / \
      9  20
         / \
        15  7

maxDepth(3)
├─ maxDepth(9)
│  ├─ maxDepth(nil) = 0
│  ├─ maxDepth(nil) = 0
│  └─ return 1 + max(0,0) = 1
├─ maxDepth(20)
│  ├─ maxDepth(15)
│  │  └─ return 1
│  ├─ maxDepth(7)
│  │  └─ return 1
│  └─ return 1 + max(1,1) = 2
└─ return 1 + max(1,2) = 3
```

时间 O(n)，空间 O(h)（h 为树高，递归栈深度）。

### 例题二：反转链表（0206）—— 链表递归

> 反转单链表。

**递归思路**：假设 `reverse(head.Next)` 已经把后面的链表反转了，现在只需把 head 接到反转后链表的末尾。

```
原链表: 1 → 2 → 3 → 4 → 5 → nil

递归反转 head.Next (即 2→3→4→5):
  假设已得: 5 → 4 → 3 → 2 → nil
  此时 head.Next(2) 仍指向 2（现在是末尾）
  head.Next.Next = head  → 2 指向 1
  head.Next = nil        → 1 指向 nil
结果: 5 → 4 → 3 → 2 → 1 → nil
```

**代码**：
```go
func reverseList(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head  // 基线：空或单节点
    }
    newHead := reverseList(head.Next)  // 反转后面的部分
    head.Next.Next = head              // 把 head 接到末尾
    head.Next = nil                    // 断开原方向
    return newHead
}
```

**关键洞察**：递归返回的是反转后链表的头，但 `head.Next` 仍指向反转后链表的**尾**，利用这一点把 head 接上去。

时间 O(n)，空间 O(n)（递归栈）。

### 例题三：合并两个有序链表（0021）—— 递归决策

> 将两个升序链表合并为一个新的升序链表。

**递归思路**：比较两个头节点，较小的那个作为结果头，它的 `Next` 指向「剩余部分的合并结果」。

```go
func mergeTwoListsRecursive(l1, l2 *ListNode) *ListNode {
    if l1 == nil {
        return l2  // 基线：一个空了，返回另一个
    }
    if l2 == nil {
        return l1
    }
    if l1.Val <= l2.Val {
        l1.Next = mergeTwoListsRecursive(l1.Next, l2)  // l1 较小，l1.Next 接续
        return l1
    }
    l2.Next = mergeTwoListsRecursive(l1, l2.Next)      // l2 较小
    return l2
}
```

**执行过程**（`l1 = 1→2→4`, `l2 = 1→3→4`）：
```
merge(1→2→4, 1→3→4): 1<=1, l1.Next = merge(2→4, 1→3→4), return 1→...
  merge(2→4, 1→3→4): 2>1, l2.Next = merge(2→4, 3→4), return 1→...
    merge(2→4, 3→4): 2<=3, l1.Next = merge(4, 3→4), return 2→...
      merge(4, 3→4): 4>3, l2.Next = merge(4, 4), return 3→...
        merge(4, 4): 4<=4, l1.Next = merge(nil, 4), return 4→...
          merge(nil, 4): return 4
        → return 4→4
      → return 3→4→4
    → return 2→3→4→4
  → return 1→2→3→4→4
→ return 1→1→2→3→4→4  ✓
```

### 例题四：翻转二叉树（0226）—— 树的递归

> 翻转一棵二叉树（交换每个节点的左右子树）。

```go
func invertTree(root *TreeNode) *TreeNode {
    if root == nil {
        return nil
    }
    root.Left, root.Right = invertTree(root.Right), invertTree(root.Left)
    return root
}
```

**精妙之处**：一行代码同时完成「递归右子树、递归左子树、交换」三件事。利用 Go 的多重赋值，先递归求出两个翻转后的子树，再交换赋值。

> 据说这是 Homebrew 作者 Max Howell 在 Google 面试时没写出的题，成了经典段子。

## 7. 递归的代价与优化

### 7.1 重复计算：记忆化

朴素递归的斐波那契 `fib(n) = fib(n-1) + fib(n-2)` 会有大量重复：

```
fib(5) 的调用树：
            fib(5)
           /      \
       fib(4)      fib(3)      ← fib(3) 算了 2 次
      /     \      /     \
   fib(3) fib(2) fib(2) fib(1)  ← fib(2) 算了 3 次
   /   \
fib(2) fib(1)
```

时间复杂度 O(2ⁿ)。**记忆化**后变为 O(n)：

```go
var memo = map[int]int{}
func fib(n int) int {
    if n <= 1 { return n }
    if v, ok := memo[n]; ok { return v }
    memo[n] = fib(n-1) + fib(n-2)
    return memo[n]
}
```

### 7.2 栈溢出：尾递归优化

**尾递归**是指递归调用是函数的**最后一步操作**（返回值直接是递归调用的结果，无后续计算）。

```go
// 非尾递归：递归后还要乘 n
func factorial(n int) int {
    if n <= 1 { return 1 }
    return n * factorial(n-1)
}

// 尾递归：用累加器 acc 把「后续计算」提前完成
func factorialTail(n, acc int) int {
    if n <= 1 { return acc }
    return factorialTail(n-1, n*acc)  // 最后一步就是递归
}
```

尾递归可被编译器优化为循环，**不增加栈帧**。但 **Go 编译器不做尾递归优化**，所以 Go 中仍需手动改写成循环来避免栈溢出。

### 7.3 改写为迭代

任何递归都可以用**显式栈**改写成迭代，模拟调用栈行为：

```go
// 递归前序遍历
func preorderRecursive(root *TreeNode) {
    if root == nil { return }
    visit(root)
    preorderRecursive(root.Left)
    preorderRecursive(root.Right)
}

// 迭代版（用栈模拟）
func preorderIterative(root *TreeNode) {
    stack := []*TreeNode{}
    for root != nil || len(stack) > 0 {
        for root != nil {
            visit(root)
            stack = append(stack, root)
            root = root.Left
        }
        root = stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        root = root.Right
    }
}
```

## 8. 递归与迭代的转换

| 维度 | 递归 | 迭代 |
|------|------|------|
| 代码简洁性 | 高（贴合问题结构） | 较低（需手动管理状态） |
| 可读性 | 对递归思维友好 | 对过程思维友好 |
| 性能 | 有函数调用开销 | 无调用开销 |
| 栈空间 | O(递归深度)，可能溢出 | O(显式栈大小)，可控 |
| 调试 | 较难（栈帧多） | 较易（状态明确） |

**选择建议**：
- 树、图的遍历 → 递归更自然
- 深度极大（n > 10⁴） → 改迭代避免栈溢出
- 性能敏感 → 迭代或尾递归
- 思路不清时 → 先写递归验证正确性，再优化

## 9. 常见误区与避坑指南

### 9.1 忘记基线条件

```go
func sum(n int) int {
    return n + sum(n-1)  // n 会变成负数，永远停不下来！
}
```
必须 `if n <= 0 { return 0 }`。

### 9.2 基线条件写错

```go
// 求链表长度
func length(head *ListNode) int {
    if head.Next == nil {  // 错！head 本身可能就是 nil
        return 1
    }
    return 1 + length(head.Next)
}
```
应改为 `if head == nil { return 0 }`。

### 9.3 规模没有真正缩小

```go
func bad(n int) int {
    return bad(n)  // n 没变，死循环！
}
```

### 9.4 重复子问题不记忆化

如前所述，朴素斐波那契是指数级的。看到重叠子问题，立刻加记忆化或改 DP。

### 9.5 误以为递归一定慢

递归有调用开销，但很多场景下开销可忽略（树遍历 O(n) 的常数因子）。不要盲目为了「性能」把清晰的递归改成晦涩的迭代。

### 9.6 忽略递归返回值的组合

```go
// 错误：忘了用递归结果
func reverseList(head *ListNode) *ListNode {
    if head == nil { return nil }
    reverseList(head.Next)  // 算了但没用！
    return head
}
```

## 10. 如何识别一道题该用递归

出现以下信号时，优先考虑递归：

| 信号 | 示例 |
|------|------|
| 问题涉及**树/链表**等递归定义的结构 | 二叉树遍历、反转链表 |
| 问题可表述为「**对子结构做同样的事**」 | 翻转左右子树 |
| 有**嵌套/自相似**结构 | 括号匹配、表达式解析 |
| 数据规模较小且可**分治** | 归并排序、快速排序 |
| 需要枚举所有方案（**回溯**） | 全排列、子集 |
| 数学定义本身是递推式 | 阶乘、组合数 |

**反信号**：
- 数据规模极大（n > 10⁶）→ 递归深度可能爆栈
- 只需求一个数值最优且有重叠子问题 → 直接 DP
- 明显的单调扫描 → 双指针/滑动窗口

## 结语

递归的本质是**信任**——信任你的函数对更小规模的输入能正确工作，然后在此基础上构造当前层的答案。这种「假设子问题已解决」的思维，是递归最强大的地方，也是最难跨越的心理障碍。

记住三句话：
1. **先写基线，再写递归**
2. **假设子问题已解决，只关心当前层如何组合**
3. **数据结构是递归的，操作就用递归**

一旦跨过这道坎，你会发现树、链表、分治、回溯的世界豁然开朗。
