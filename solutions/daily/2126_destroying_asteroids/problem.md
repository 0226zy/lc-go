# 2126. 摧毁小行星 (Destroying Asteroids)

## 题目描述

给你一个整数 `mass` 表示一个行星的**初始质量**，再给你一个整数数组 `asteroids`，其中 `asteroids[i]` 是第 `i` 个小行星的质量。

**规则**：
- 行星可以与小行星碰撞，如果行星的质量 **大于等于** 小行星的质量，则可以摧毁小行星，并且行星的质量 **增加** 小行星的质量。
- 如果行星的质量 **小于** 小行星的质量，则行星会被摧毁，游戏结束。

**目标**：判断是否有可能 **按顺序**（从左到右）摧毁所有小行星。

如果能摧毁所有小行星，返回 `true`；否则返回 `false`。

---

### 示例 1

```
输入：mass = 10, asteroids = [3,9,19,5,21]
输出：true
解释：
- 初始质量 10 >= 3，摧毁后质量变为 13
- 13 >= 9，摧毁后质量变为 22
- 22 >= 19，摧毁后质量变为 41
- 41 >= 5，摧毁后质量变为 46
- 46 >= 21，摧毁后质量变为 67
所有小行星都被摧毁，返回 true。
```

### 示例 2

```
输入：mass = 5, asteroids = [4,9,23,4]
输出：false
解释：
- 初始质量 5 >= 4，摧毁后质量变为 9
- 9 < 9 不成立，9 >= 9，摧毁后质量变为 18
- 18 < 23，行星被摧毁，返回 false。
```

---

## 提示

- `1 <= mass <= 10^5`
- `1 <= asteroids.length <= 10^5`
- `1 <= asteroids[i] <= 10^5`

---

## 题目解析

### 核心思路

这道题使用 **贪心算法**：

1. **排序小行星**：将小行星按质量从小到大排序。
2. **贪心碰撞**：从左到右遍历排序后的小行星：
   - 如果行星质量 `>=` 小行星质量，摧毁它，行星质量增加。
   - 如果行星质量 `<` 小行星质量，返回 `false`（无法摧毁）。
3. 如果遍历完所有小行星都成功摧毁，返回 `true`。

**为什么排序是正确的？**
- 因为行星只能按顺序摧毁小行星，如果当前行星质量不足以摧毁最小的小行星，那么更大的小行星更不可能被摧毁。
- 摧毁小行星后行星质量会增加，所以优先摧毁小的可以最大化后续摧毁的可能性。

---

### 算法步骤

1. 将 `asteroids` 数组排序（从小到大）。
2. 初始化 `curMass = mass`。
3. 遍历排序后的 `asteroids`：
   - 如果 `curMass >= asteroids[i]`，则 `curMass += asteroids[i]`。
   - 否则返回 `false`。
4. 返回 `true`。

---

### 复杂度分析

- **时间复杂度**: `O(n log n)` — 排序占主导，遍历是 `O(n)`。
- **空间复杂度**: `O(1)` 或 `O(n)` — 取决于排序算法的额外空间（`sort.Ints` 是 `O(n)`）。

---

## 代码实现

### 最优解：排序 + 贪心

```go
func asteroidsDestroyed(mass int, asteroids []int) bool {
    // 1. 排序
    sort.Ints(asteroids)
    
    // 2. 贪心碰撞
    curMass := mass
    for _, ast := range asteroids {
        if curMass >= ast {
            curMass += ast
        } else {
            return false
        }
    }
    return true
}
```

**执行过程示例**（`mass = 10, asteroids = [3,9,19,5,21]`）：

```
排序后：[3, 5, 9, 19, 21]
curMass = 10
i=0: 10 >= 3 ✅ curMass = 13
i=1: 13 >= 5 ✅ curMass = 18
i=2: 18 >= 9 ✅ curMass = 27
i=3: 27 >= 19 ✅ curMass = 46
i=4: 46 >= 21 ✅ curMass = 67
返回 true
```

---

### 关键点

1. **排序是核心**：必须从小到大排序，这样才能最大化摧毁可能性。
2. **整数溢出问题**：`mass` 和 `asteroids[i]` 最大都是 `10^5`，数组长度最大 `10^5`，所以总质量最大是 `10^5 + 10^5 * 10^5 = 10^10 + 10^5`，**超出 int32 范围**，但在 **int64（Go 的 int 是 64 位）范围内**，所以 Go 不会有溢出问题。
3. **边界情况**：
   - 如果 `asteroids` 为空，直接返回 `true`。
   - 如果 `mass` 初始就大于等于所有小行星，直接返回 `true`。

---

### 性能优势

- `O(n log n)` 时间复杂度，是最优解法。
- 排序后单次遍历，缓存友好。
- 原地排序，空间复杂度低。
