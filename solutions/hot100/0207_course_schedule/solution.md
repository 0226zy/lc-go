# 207. 课程表 — 解法详解

## 一句话总结

> **把课程看成有向图，"能不能修完所有课"等价于"图里有没有环"。** 有环就死锁（A 依赖 B，B 依赖 A），无环就能修完。检测环的方法就是**拓扑排序**。

---

## 1. 把题目翻译成图

### 1.1 建图

`prerequisites = [[1, 0], [2, 1], [3, 2]]` 表示：

```
0 → 1 → 2 → 3
```

- 课程是**节点**（0, 1, 2, 3）
- 依赖关系是**有向边**：`[1, 0]` 表示 `0 → 1`（先修 0 才能修 1）
- 边的方向 = 学习顺序的方向

### 1.2 核心洞察

| 情况 | 图的结构 | 能否修完 |
|------|---------|---------|
| 依赖形成链 | `0→1→2→3` | ✅ 能 |
| 依赖形成环 | `0→1→0` | ❌ 不能 |
| 无依赖 | 孤立节点 | ✅ 能 |

**结论**：问题转化为 **"有向图是否存在环"**。

### 1.3 什么是拓扑排序

> 拓扑排序是对有向无环图（DAG）的线性排序，使得对每条边 `u→v`，`u` 都排在 `v` 前面。

通俗说：**把所有课程排成一排，排在前面的一定先修。**

- 能排出来 → 无环 → 返回 `true`
- 排不出来 → 有环 → 返回 `false`

## 2. 解法一：BFS（Kahn 算法）

### 2.1 生活化比喻

想象你在选课：
1. 先看**哪些课没有任何先修要求**（入度为 0）→ 这些课现在就能选
2. 选完这些课后，新的课可能就没有先修要求了 → 继续选
3. 如果最后所有课都选完了 → 没有环 → `true`
4. 如果还有课选不了 → 它们互相依赖形成环 → `false`

### 2.2 关键概念：入度

> **入度** = 有多少条边指向这个节点 = 这门课有多少个先修课。

```
0 → 1 → 2 → 3
```

| 课程 | 入度 | 含义 |
|------|------|------|
| 0 | 0 | 没有先修，现在就能选 |
| 1 | 1 | 先修 0 |
| 2 | 1 | 先修 1 |
| 3 | 1 | 先修 2 |

### 2.3 算法步骤

```
1. 建图 + 算入度
2. 所有入度为 0 的节点入队（没有先修的课，现在就能选）
3. 循环出队：
   - 取出一个入度为 0 的课（选了它）
   - 把它指向的后继课程的入度都减 1（这门先修课搞定了）
   - 如果某个后继入度变成 0 → 它也能选了 → 入队
4. 如果最后选完的课 == 总课程数 → true，否则 → false
```

### 2.4 图解过程

以 `numCourses = 4, prerequisites = [[1,0],[2,1],[3,2]]` 为例：

```
初始：
  0 → 1 → 2 → 3
  入度: [0, 1, 1, 1]
  队列: [0]          ← 入度为 0 的先入队
  已选: 0

第1轮：取出 0
  0 的后继是 1，入度 1→0
  入度: [0, 0, 1, 1]
  队列: [1]          ← 1 入度变 0，入队
  已选: 0, 1

第2轮：取出 1
  1 的后继是 2，入度 1→0
  入度: [0, 0, 0, 1]
  队列: [2]
  已选: 0, 1, 2

第3轮：取出 2
  2 的后继是 3，入度 1→0
  入度: [0, 0, 0, 0]
  队列: [3]
  已选: 0, 1, 2, 3

第4轮：取出 3
  3 没有后继
  队列: []
  已选: 0, 1, 2, 3 = 4 = numCourses ✅
```

### 2.5 反例：有环的情况

以 `numCourses = 2, prerequisites = [[1,0],[0,1]]` 为例：

```
初始：
  0 ⇄ 1    （互相依赖，形成环）
  入度: [1, 1]
  队列: []    ← 没有入度为 0 的课！
  已选: 0

循环不执行（队列为空）
已选: 0 ≠ 2 = numCourses ❌ → 返回 false
```

### 2.6 代码实现

```go
func CanFinish(numCourses int, prerequisites [][]int) bool {
    // 1. 建邻接表 + 算入度
    graph := make([][]int, numCourses)
    inDegree := make([]int, numCourses)
    for _, p := range prerequisites {
        // p = [a, b] 表示 b → a
        graph[p[1]] = append(graph[p[1]], p[0])
        inDegree[p[0]]++
    }

    // 2. 入度为 0 的节点入队
    queue := []int{}
    for i := 0; i < numCourses; i++ {
        if inDegree[i] == 0 {
            queue = append(queue, i)
        }
    }

    // 3. BFS 逐个"选课"
    count := 0
    for len(queue) > 0 {
        curr := queue[0]
        queue = queue[1:]
        count++
        for _, next := range graph[curr] {
            inDegree[next]--
            if inDegree[next] == 0 {
                queue = append(queue, next)
            }
        }
    }

    // 4. 选完所有课 = 无环
    return count == numCourses
}
```

### 2.7 复杂度

- **时间 O(V + E)**：每个节点入队出队各一次，每条边被访问一次。
- **空间 O(V + E)**：邻接表 + 入度数组 + 队列。

## 3. 解法二：DFS 检测环

### 3.1 生活化比喻

想象你在规划学习路径，从某门课开始往下探：
1. 如果探着探着**又回到了自己** → 环！死锁了！
2. 如果一条路探到底没回到自己 → 这条路安全，标记为"已完成"
3. 已完成的课再被探到时直接跳过，不用重复检查

### 3.2 三色标记法

每个节点有三种状态：

| 颜色 | 状态 | 含义 |
|------|------|------|
| **白** (0) | 未访问 | 还没探过 |
| **灰** (1) | 正在访问 | 在当前递归路径上 |
| **黑** (2) | 已完成 | 已经探完，安全 |

**核心规则**：DFS 过程中如果遇到一个**灰色**节点 → 说明绕回来了 → **有环**！

### 3.3 图解过程

无环情况 `0 → 1 → 2`：

```
访问 0：0 变灰
  访问 1：1 变灰
    访问 2：2 变灰
      2 没有后继，2 变黑 ← 完成
    1 变黑 ← 完成
  0 变黑 ← 完成
无环 ✅
```

有环情况 `0 → 1 → 0`：

```
访问 0：0 变灰
  访问 1：1 变灰
    访问 0：0 是灰色！← 绕回来了，有环！
返回 false ❌
```

### 3.4 为什么要"黑"色？

考虑钻石形依赖：

```
    0
   / \
  1   2
   \ /
    3
```

如果不用黑色标记：
- 从 0 出发 → 1 → 3（3 完成）
- 回到 0 → 2 → 3（3 又被访问一次！）

有了黑色标记：
- 3 第一次完成后变黑
- 2 再访问 3 时发现是黑色 → 直接跳过，不重复处理

### 3.5 代码实现

```go
func CanFinish(numCourses int, prerequisites [][]int) bool {
    graph := make([][]int, numCourses)
    for _, p := range prerequisites {
        graph[p[1]] = append(graph[p[1]], p[0])
    }

    // 0=未访问, 1=正在访问(灰), 2=已完成(黑)
    color := make([]int, numCourses)

    var dfs func(node int) bool
    dfs = func(node int) bool {
        if color[node] == 1 {
            return false // 遇到灰色，有环！
        }
        if color[node] == 2 {
            return true // 黑色，已确认安全
        }
        color[node] = 1 // 标记为灰色（进入递归路径）
        for _, next := range graph[node] {
            if !dfs(next) {
                return false
            }
        }
        color[node] = 2 // 标记为黑色（探完，安全）
        return true
    }

    for i := 0; i < numCourses; i++ {
        if !dfs(i) {
            return false
        }
    }
    return true
}
```

### 3.6 复杂度

- **时间 O(V + E)**：每个节点访问一次，每条边检查一次。
- **空间 O(V + E)**：邻接表 + color 数组 + 递归栈 O(V)。

## 4. 两种解法对比

| 维度 | BFS (Kahn) | DFS (三色标记) |
|------|-----------|---------------|
| **核心思想** | 不断删入度为 0 的点 | 递归探路，遇灰则环 |
| **检测环** | count ≠ numCourses | 遇到灰色节点 |
| **输出** | 天然得到拓扑序 | 只能判断有无环 |
| **直觉** | "先做没依赖的" | "探到底看是否绕回" |
| **空间** | O(V+E) 无递归 | O(V+E) + 递归栈 |
| **适合** | 需要拓扑序时 | 只需判断环时 |

### 选择建议

- **只需判断能否修完** → 两种都行，DFS 更简洁
- **需要输出选课顺序** → 用 BFS（Kahn），队列出队顺序就是拓扑序
- **担心递归栈溢出** → 用 BFS（课程数 ≤ 2000，DFS 不会溢出）

## 5. 常见误区

### 5.1 边的方向搞反

```go
// ❌ 错误：搞反了方向
graph[p[0]] = append(graph[p[0]], p[1])  // a → b？

// ✅ 正确：[a, b] 表示 b → a（先修 b 才能修 a）
graph[p[1]] = append(graph[p[1]], p[0])  // b → a
```

**记忆技巧**：`[1, 0]` = "学 1 要先学 0" = 0 在前，所以边是 `0 → 1`。

### 5.2 BFS 忘记所有入度为 0 的节点都入队

```go
// ❌ 错误：只入队第一个
queue = []int{0}

// ✅ 正确：所有入度为 0 的都入队
for i := 0; i < numCourses; i++ {
    if inDegree[i] == 0 {
        queue = append(queue, i)
    }
}
```

### 5.3 DFS 不用三色，只用 visited

```go
// ❌ 只有 visited，无法区分"在路径上"和"已完成"
if visited[node] { return ... }

// ✅ 三色标记，区分"灰色（路径上）"和"黑色（已完成）"
if color[node] == 1 { return false } // 灰色 = 环
if color[node] == 2 { return true }  // 黑色 = 安全
```

只用 `visited` 的话，钻石形依赖会把已完成的节点误判为环。

## 7. 总结

```
课程表问题
  ↓ 翻译成图
有向图是否有环
  ↓ 两种方法
BFS (Kahn)           DFS (三色标记)
  ↓                     ↓
不断删入度=0的节点     递归探路遇灰则环
  ↓                     ↓
count == V ? true      无灰相遇 ? true
```

**记忆口诀**：BFS 删零入度看计数，DFS 三色遇灰即有环。
