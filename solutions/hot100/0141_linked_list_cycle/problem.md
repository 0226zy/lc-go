# 141. 环形链表 (Linked List Cycle)

## 题目描述

给你一个链表的头节点 `head`，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。**注意：`pos` 不作为参数进行传递**。仅仅是为了标识链表的实际情况。

*如果链表中存在环*，则返回 `true`。否则，返回 `false`。

**示例 1：**
```
输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，其尾部连接到第二个节点。
```

**示例 2：**
```
输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，其尾部连接到第一个节点。
```

**示例 3：**
```
输入：head = [1], pos = -1
输出：false
解释：链表中没有环。
```

**提示：**
- 链表中节点的数目范围是 `[0, 10^4]`
- `-10^5 <= Node.val <= 10^5`
- `pos` 为 `-1` 或者链表中的有效索引

**进阶：** 你能用 O(1)（即，常量）内存解决此问题吗？

---

## 思路解析

### 方法一：哈希表法（空间 O(n)）

**核心思想：** 遍历链表，用哈希表记录每个访问过的节点。如果再次遇到已访问的节点，则说明有环。

**算法步骤：**
1. 创建一个哈希表（Go 中用 `map[*ListNode]bool`）
2. 遍历链表，对于每个节点：
   - 如果节点已在哈希表中，返回 `true`（有环）
   - 否则，将节点加入哈希表
3. 如果遍历到 `nil`，说明无环，返回 `false`

**复杂度分析：**
- 时间复杂度：O(n)，遍历一次链表
- 空间复杂度：O(n)，哈希表需要存储所有节点

---

### 方法二：快慢指针法（Floyd 判圈算法，空间 O(1)）

**核心思想：** 使用两个指针，一个快指针（每次走两步），一个慢指针（每次走一步）。如果链表有环，快指针最终会追上慢指针（两者相遇）。

**算法步骤：**
1. 初始化 `slow = head`，`fast = head`
2. 当 `fast != nil` 且 `fast.Next != nil` 时：
   - `slow = slow.Next`（慢指针走一步）
   - `fast = fast.Next.Next`（快指针走两步）
   - 如果 `slow == fast`，说明有环，返回 `true`
3. 如果 `fast` 或 `fast.Next` 为 `nil`，说明无环，返回 `false`

**为什么快指针一定会追上慢指针？**
- 如果链表有环，快指针和慢指针都会进入环中
- 快指针每次比慢指针多走一步，相当于在环中快指针以速度 1 接近慢指针
- 最终快指针一定会追上慢指针（两者相遇）

**复杂度分析：**
- 时间复杂度：O(n)，最坏情况遍历两次链表
- 空间复杂度：O(1)，只使用两个指针

---

### 方法三：标记法（修改链表节点，空间 O(1)）

**核心思想：** 遍历链表，将访问过的节点标记为特殊值（如 `math.MinInt32`）。如果再次遇到标记过的节点，则说明有环。

**注意：** 这种方法会修改链表的值，不推荐在实际项目中使用（除非明确要求 O(1) 空间且可以修改链表）。

**算法步骤：**
1. 遍历链表，对于每个节点：
   - 如果节点的值已经被标记为特殊值，返回 `true`（有环）
   - 否则，将节点的值改为特殊值（如 `math.MinInt32`）
2. 如果遍历到 `nil`，说明无环，返回 `false`

**复杂度分析：**
- 时间复杂度：O(n)，遍历一次链表
- 空间复杂度：O(1)，只使用常数额外空间

**缺点：** 会破坏链表原始数据，且如果链表节点值本来就是特殊值，会误判。

---

## 知识点总结

1. **快慢指针**：用于判断链表是否有环，或找到环的入口
2. **哈希表**：记录访问过的节点，空间换时间
3. **Floyd 判圈算法**：快慢指针法的正式名称，还可以用于找到环的入口节点
