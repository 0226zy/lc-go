# 300. 最长递增子序列 (Longest Increasing Subsequence)

## 题目描述

给定一个整数数组 `nums`，找到其中最长严格递增子序列的长度。

**子序列** 是由数组派生而来的序列，删除（或不删除）数组中的元素而不改变其余元素的顺序。例如，`[3,6,2,7]` 是数组 `[0,3,1,6,2,2,7]` 的子序列。

### 示例 1

```
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]，因此长度为 4 。
```

### 示例 2

```
输入：nums = [0,1,0,3,2,3]
输出：4
```

### 示例 3

```
输入：nums = [7,7,7,7,7,7,7]
输出：1
```

## 提示

- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`

## 题目解析

### 核心思路

本题使用**动态规划**求解。

定义 `dp[i]` 为：以 `nums[i]` 结尾的最长严格递增子序列的长度。

为什么定义“以 nums[i] 结尾”？因为这样可以利用前面已计算的结果进行状态转移。如果已知以 `nums[j]`（`j < i`）结尾的最长递增子序列长度，那么当 `nums[i] > nums[j]` 时，就可以将 `nums[i]` 接在该子序列后面，形成以 `nums[i]` 结尾、长度为 `dp[j] + 1` 的递增子序列。

### 算法步骤

1. **初始化**：创建一个长度与 `nums` 相同的 `dp` 数组，每个位置初始化为 `1`。因为每个元素自身至少可以构成长度为 1 的递增子序列。
2. **状态转移**：遍历每个位置 `i`（从 1 到 n-1），对于每个 `i`，再遍历其之前的所有位置 `j`（从 0 到 i-1）：
   - 若 `nums[i] > nums[j]`，说明 `nums[i]` 可以接在以 `nums[j]` 结尾的递增子序列后面，更新 `dp[i] = max(dp[i], dp[j] + 1)`。
3. **记录答案**：在遍历过程中维护一个变量 `res`，每次更新 `dp[i]` 后，用 `res = max(res, dp[i])` 记录最大值。
4. **返回结果**：最终 `res` 即为整个数组的最长递增子序列长度。

### 复杂度分析

- **时间复杂度**: O(n²)，双重循环，外层遍历每个元素，内层遍历其之前的所有元素。
- **空间复杂度**: O(n)，需要额外的 `dp` 数组存储中间状态。

## 方法二：耐心排序 + 二分查找（最优解）

### 核心思想

维护一个 `tails` 数组，`tails[k]` 表示**长度为 k+1 的递增子序列的最小末尾元素**。

直觉：对于同样长度的递增子序列，末尾元素越小，后续能接上的元素越多，越有利于构造更长的子序列。因此我们只关心「每个长度对应的最小末尾」。

### 算法步骤

1. **初始化**：`tails = [nums[0]]`
2. **遍历** `nums[1:]`，对每个 `nums[i]`：
   - 若 `nums[i] > tails` 末尾 → 直接追加（扩展最长长度）
   - 否则 → 在 `tails` 中二分查找**第一个 ≥ nums[i]** 的位置，替换之
3. **返回** `len(tails)` 即为 LIS 长度

> ⚠️ 注意：`tails` 数组**并不代表真实的 LIS**，其长度才等于 LIS 长度。替换操作是为了让同长度的末尾尽可能小。

### 执行过程示例（nums = [10,9,2,5,3,7,101,18]）

```
i=0: tails=[10]                      ← 初始化
i=1: 9 < 10, 替换 tails[0]=9  → tails=[9]
i=2: 2 < 9,  替换 tails[0]=2  → tails=[2]
i=3: 5 > 2,  追加           → tails=[2,5]
i=4: 3 < 5,  替换 tails[1]=3  → tails=[2,3]
i=5: 7 > 3,  追加           → tails=[2,3,7]
i=6: 101 > 7,追加           → tails=[2,3,7,101]
i=7: 18 < 101,替换 tails[3]=18 → tails=[2,3,7,18]
结果: len(tails) = 4 ✓
```

### 为什么正确？

**关键不变量**：`tails` 始终保持严格递增，且 `tails[k]` 是当前已扫描元素中、长度为 k+1 的递增子序列的最小末尾。

- 替换不改变 `tails` 长度，但让同长度末尾更小，为未来扩展留空间
- 追加意味着找到了更长的递增子序列
- 每次操作后 `tails` 仍递增（因为替换位置是第一个 ≥ target 的，替换后仍 ≤ 后继）

### 复杂度分析

- **时间复杂度**: O(n log n)，每个元素做一次二分查找。
- **空间复杂度**: O(n)，`tails` 数组。

## 两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 动态规划 | O(n²) | O(n) | n 较小（≤2500），思路直观 |
| 二分查找 | O(n log n) | O(n) | n 较大，追求最优性能 |

当 n = 2500 时，O(n²) ≈ 625 万次操作仍可接受；n 更大时二分解法优势明显。
