# 305. 岛屿数量 II

> 难度：困难 ｜ 分类：图 ｜ 尊享面试 100 题 · 第 58 题
> 链接：https://leetcode.cn/problems/number-of-islands-ii/

## 题目描述

给你一个大小为 `m × n` 的二维网格，最初网格中全部是**水**（值为 0）。给你一个数组 `positions`，其中 `positions[i] = [ri, ci]` 表示在第 `i` 次操作中，把位置 `(ri, ci)` 的水变成**陆地**（值为 1）。

当一块陆地与另一块陆地在**上、下、左、右**四个方向上相邻时，它们属于同一个岛屿。两个岛屿之间不会相邻。

请你返回一个整数数组 `answer`，其中 `answer[i]` 表示执行完第 `i` 次 `positions` 操作后，网格中岛屿的数量。

**注意**：同一个位置可能被重复添加（`(ri, ci)` 可能多次出现），重复填海不会产生新的陆地。

### 示例 1

```
输入: m = 3, n = 3, positions = [[0,0],[0,1],[1,2],[2,1]]
输出: [1,1,2,3]
解释:
  第 1 步: 在 (0,0) 填海 → 1 个岛屿
  第 2 步: 在 (0,1) 填海，与 (0,0) 相邻合并 → 1 个岛屿
  第 3 步: 在 (1,2) 填海，孤立 → 2 个岛屿
  第 4 步: 在 (2,1) 填海，孤立 → 3 个岛屿
```

### 示例 2

```
输入: m = 1, n = 1, positions = [[0,0]]
输出: [1]
解释: 只有一格，填海后形成 1 个岛屿。
```

### 提示

- `1 <= m, n, positions.length <= 10^4`
- `1 <= m * n <= 10^4`
- `positions[i].length == 2`
- `0 <= ri < m`
- `0 <= ci < n`

**进阶**：你能在 O(k log(mn)) 甚至接近 O(k) 的时间复杂度内完成吗？其中 `k = positions.length`。

## 思路解析

### 核心思路

每填一块陆地，网格的连通关系就发生一次变化——这正是**并查集（Union-Find）**擅长的「动态连通性」场景。岛屿数量可以按如下方式增量维护：

- 新增一块陆地时，先把它当作一个孤立岛屿，`count++`；
- 然后检查它四个方向的邻居，凡是已经是陆地的邻居，用并查集把二者合并——如果二者原本不连通（`Union` 返回 true），说明两块岛屿被连成了一块，`count--`；
- 若该位置本来就是陆地（重复操作），直接沿用当前 `count`。

二维坐标 `(r, c)` 映射到一维编号 `r * n + c` 即可套用到标准并查集上。配合路径压缩与按秩合并，单次合并/查询的均摊复杂度接近 O(α(mn))，α 为反阿克曼函数，实际可视为常数。

注意：并查集模板自带的 `Count` 从 `m*n` 开始计数（假设所有格子独立），不符合本题「初始全为水」的语义，因此岛屿数量需自行用 `count` 变量维护。

### 算法步骤

1. 建立大小为 `m*n` 的并查集，另用 `grid` 标记每个格子是否已是陆地，`count` 记录当前岛屿数。
2. 依次处理每个位置 `(r, c)`：
   - 若 `grid[r][c]` 已是陆地（重复操作），把当前 `count` 写入答案，跳过后续步骤；
   - 否则置 `grid[r][c] = 1`，`count++`；
   - 遍历四个方向的邻居：若邻居在界内且是陆地，调用 `Union` 合并，若合并成功（原本不连通）则 `count--`；
   - 把 `count` 追加到答案数组。
3. 返回答案数组。

## 复杂度分析

- **时间复杂度**: O(k × α(mn))，k 为操作次数；每次操作最多做 4 次 Union/Find，均摊代价接近常数，实践中近似 O(k)。
- **空间复杂度**: O(m × n)，并查集的父数组、秩数组与 `grid` 标记数组各需一份网格大小的空间。
