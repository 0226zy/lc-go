# 1231. 分享巧克力

> 难度：困难 ｜ 分类：二分查找 ｜ 尊享面试 100 题 · 第 78 题
> 链接：https://leetcode.cn/problems/divide-chocolate/

## 题目描述

你有一大块巧克力，它由一些甜度不完全相同的小块组成，我们用数组 `sweetness` 来表示每一小块的甜度。

你打算和 `k` 名朋友一起分享这块巧克力，所以你需要将巧克力切割成 `k + 1` 块（**切 `k` 次**，每块都是原数组中连续的一段，且不能为空），然后把它们分给你的朋友们吃。

你非常慷慨，只吃甜度**最小**的那一块，其余的都分给朋友们。

请找出最佳的切割策略，使得你所分得的巧克力块的甜度**尽可能大**，并返回这个最大甜度。

### 示例 1

```
输入: sweetness = [1,2,3,4,5,6,7,8,9], k = 5
输出: 6
解释: 一种最优分法是 [1,2,3], [4,5], [6], [7], [8], [9]，
     你吃到的块甜度为 1+2+3=6，是所有分法中「最小块的甜度」的最大值。
```

### 示例 2

```
输入: sweetness = [5,6,7,8,9,1,2,3,4], k = 8
输出: 1
解释: 需要分成 9 块，但数组只有 9 个元素，只能每个元素单独一块，
     最小块的甜度为 1。
```

### 示例 3

```
输入: sweetness = [1,2,2,1,2,2,1,2,2], k = 2
输出: 5
解释: 一种最优分法是 [1,2,2], [1,2,2], [1,2,2]，每块甜度都是 5。
```

### 提示

- `0 <= k < sweetness.length <= 10^4`
- `1 <= sweetness[i] <= 10^5`

## 思路解析

### 核心思路

这是典型的「**最大值最小化**」问题（最大化最小块甜度），答案具有**单调性**：如果我们能做到「每块甜度都不小于 `x`」，那么任何比 `x` 小的值也一定能做到；反之如果 `x` 做不到，比 `x` 大的值也都做不到。因此可以对答案 `x` 做**二分查找**。

判定函数 `check(x)`：能否把数组切成**至少** `k + 1` 块、且每块甜度之和都 `>= x`？用**贪心**即可——从左到右累加，一旦当前累加和达到 `x` 就切一刀、重新累加。贪心正确的原因：越早切下一块，留给后面的元素越多，后面越容易凑出满足条件的块；所以「能切出的块数」取最大值时贪心的切法不会更差。只要能切出 `>= k + 1` 块，就可以把多余的块合并给邻居（块只会变大），正好凑出 `k + 1` 块。

二分范围：下界为 `1`（每小块甜度至少为 1），上界为数组总和 `sum`（只切 0 刀时自己的那块就是全部）。在 `[lo, hi]` 上找满足 `check(x)` 的最大 `x`。

### 算法步骤

1. 计算总和 `sum`，令二分区间 `lo = 1`，`hi = sum`。
2. 当 `lo < hi` 时，取 `mid = (lo + hi + 1) / 2`（向上取整，避免死循环）：
   - 若 `check(mid)` 成立（能切出至少 `k + 1` 块甜度都不小于 `mid` 的块），说明答案可以更大，令 `lo = mid`；
   - 否则令 `hi = mid - 1`。
3. 返回 `lo`。

其中 `check(x)`：

1. `cnt = 0`，`cur = 0`；
2. 遍历 `sweetness`，`cur += sweetness[i]`；当 `cur >= x` 时，`cnt++` 并把 `cur` 清零；
3. 返回 `cnt >= k + 1`。

## 复杂度分析

- **时间复杂度**: O(n log S)。`n` 为数组长度，`S` 为数组元素总和；二分最多 log S 轮，每轮 `check` 需要 O(n) 的线性扫描。
- **空间复杂度**: O(1)。只用到了常数个变量。
