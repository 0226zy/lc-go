# 642. 设计搜索自动补全系统

> 难度：困难 ｜ 分类：前缀树 ｜ 尊享面试 100 题 · 第 69 题
> 链接：https://leetcode.cn/problems/design-search-autocomplete-system/

## 题目描述

设计一个搜索自动补全系统。系统初始化时给定一批历史句子 `sentences` 及它们的热度 `times`（被搜索的次数）。用户逐字符输入，系统需要实时给出以当前输入为**前缀**的、热度最高的至多 **3** 个句子。

实现以下操作：

- `AutocompleteSystem(String[] sentences, int[] times)`：初始化系统，`sentences[i]` 的热度为 `times[i]`。
- `List<String> input(char c)`：
  - 如果 `c == '#'`：表示输入结束，把当前已输入的完整句子记入历史（热度加 1），清空当前输入，返回空列表；
  - 否则：把字符 `c` 追加到当前输入，返回以当前输入为前缀、热度最高的至多 3 个句子。
  - 排序规则：先按**热度降序**；热度相同时按 **ASCII 字典序升序**。

### 示例 1

```
输入:
  ["AutocompleteSystem", "input", "input", "input", "input"]
  [[["i love you", "island", "iroman", "i love leetcode"], [5, 3, 2, 2]], ["i"], [" "], ["a"], ["#"]]
输出:
  [null, ["i love you", "island", "i love leetcode"], ["i love you", "i love leetcode"], [], []]
解释:
  输入 'i'：前缀 "i" 匹配全部 4 句，取热度前 3（热度相同按字典序）；
  输入 ' '：前缀 "i " 只匹配两个 "i love ..." 句子；
  输入 'a'：前缀 "i a" 无匹配，返回空；
  输入 '#'：把 "i a" 记入历史并清空当前输入。
```

### 示例 2

```
输入:
  ["AutocompleteSystem", "input", "input", "input"]
  [[["abc", "ab", "a"], [1, 2, 3]], ["a"], ["#"], ["a"]]
输出:
  [null, ["a", "ab", "abc"], null, ["a", "ab", "abc"]]
解释:
  首次输入 'a' 时三句全匹配，按热度排序为 a(3)、ab(2)、abc(1)；
  输入 '#' 后 "a" 的热度变为 4；再次输入 'a' 时排序不变。
```

### 提示

- `n == sentences.length == times.length`
- `1 <= n <= 100`
- `1 <= sentences[i].length <= 100`
- `0 <= times[i] <= 50`
- `sentences[i]` 由小写字母和空格组成，`c` 是小写字母、空格或 `'#'`
- 每个测试用例中 `input` 最多调用 `5000` 次，总输入字符数不超过 `5000`

## 思路解析

### 核心思路

用一张**哈希表 `hot`** 维护每个句子的当前热度（历史句子和 `#` 新增的句子都在这张表里），再维护一个 `cur` 字符串表示当前已输入的前缀。

每次 `input(c)`：

- `c == '#'`：`hot[cur]++`，清空 `cur`，返回空；
- 否则：`cur += c`，遍历 `hot` 中所有句子，筛出以 `cur` 为前缀的候选，按「热度降序、字典序升序」排序后取前 3。

因为题目给定的句子数 `n ≤ 100`、调用次数 `≤ 5000`，这种「全量扫描 + 排序」的做法完全够快（总量约 5000 × 100 × 100 = 5×10^7 次字符比较）。如果句子量更大，可以把哈希表换成**前缀树**：每个 Trie 节点缓存「该前缀下热度前 3 的句子」，每次输入一个字符只需沿树走一步，O(1) 出结果——这是本题的进阶优化方向。

### 算法步骤

1. 构造器：把 `sentences[i] -> times[i]` 放入 `hot` 哈希表，`cur` 置空。
2. `input(c)`：
   - 若 `c == '#'`：`hot[cur]++`，`cur = ""`，返回空列表；
   - 否则把 `c` 追加到 `cur`。
3. 遍历 `hot`，用 `strings.HasPrefix(sentence, cur)` 收集候选。
4. 对候选按「热度降序，热度相同按 ASCII 字典序升序」排序。
5. 取前 `min(3, len(候选))` 个返回。

## 复杂度分析

设历史句子数为 `n`，句子平均长度为 `L`，一次 `input` 命中的候选数为 `k`。

- **时间复杂度**:
  - `input('#')`：O(1)（哈希表更新）；
  - `input(其他)`：O(n·L + k·log k)，扫描所有句子做前缀判断 O(n·L)，排序 O(k·log k)。
- **空间复杂度**: O(n·L)，哈希表存储所有句子及其热度；`cur` 额外占用 O(L)。
