# 1423. 可获得的最大点数 (Maximum Points You Can Obtain from Cards)

## 题目描述

几张卡牌 **排成一行**，每张卡牌都有一个对应的点数。点数由整数数组 `cardPoints` 给出。

每次行动，你可以从行的开头拿走一张卡牌，或者从行的末尾拿走一张卡牌。最终你必须正好拿 `k` 张卡牌。

你的点数就是你拿到手中的所有卡牌的点数之和。

给你一个整数数组 `cardPoints` 和整数 `k` ，请你返回可以获得的 **最大点数** 。

### 示例 1

```
输入: cardPoints = [1,2,3,4,5,6,1], k = 3
输出: 12
解释: 第一次行动，不管你拿哪张牌，你的点数总是 1。但是，先拿最右边的卡牌将会最大化你的可获得点数。
最优策略是拿右边的三张卡牌，最终点数为 1 + 6 + 5 = 12。
```

### 示例 2

```
输入: cardPoints = [2,2,2], k = 2
输出: 4
解释: 无论你拿起哪两张卡牌，可获得的点数总是 4。
```

### 示例 3

```
输入: cardPoints = [9,7,7,9,7,7,9], k = 7
输出: 55
解释: 你必须拿起所有卡牌，可以获得的点数为所有卡牌的点数之和。
```

## 提示

- `1 <= cardPoints.length <= 10^5`
- `1 <= cardPoints[i] <= 10^4`
- `1 <= k <= cardPoints.length`

## 题目解析

### 核心思路

直接枚举「从左边拿 i 张、从右边拿 k-i 张」的 k+1 种方案也可以做（前缀和），但有一个更漂亮的转化：

**拿走 k 张牌（只能从头或尾拿），等价于剩下一段长度为 `n - k` 的连续子数组。**

因为从头尾轮流拿走任意多张牌之后，剩下的牌在原始数组中一定是连续的一段。所以：

> 最大拿牌点数 = 数组总和 - 长度为 `n - k` 的连续子数组的最小点数和

问题就转化为经典的 **固定长度滑动窗口**：求长度为 `n - k` 的窗口的最小和，再用总和减去它。

本题还有一种等价写法：直接对「左边拿 i 张 + 右边拿 k-i 张」的得分做滑动（先全拿左边 k 张，然后每次左边界右移一格、右边界补一张），本质与上面的最小窗口法互为镜像，任选其一即可。这里采用最小窗口法，更贴近滑动窗口模板。

### 算法步骤

1. 计算数组总点数 `total`。
2. 设窗口长度 `windowLen = n - k`：
   - 若 `windowLen == 0`（即 `k == n`），必须拿走所有牌，直接返回 `total`。
   - 若 `windowLen == n`（即 `k == 0`，题目约束中不出现，但保证健壮性），返回 0。
3. 计算前 `windowLen` 张牌的点数和，作为初始窗口和。
4. 窗口从左向右滑动：每次移出左端元素、移入右端元素，维护当前窗口和 `minSum` 的最小值。
5. 返回 `total - minSum`。

### 复杂度分析

- **时间复杂度**: O(n)。计算总和一次扫描 O(n)，滑动窗口一次扫描 O(n)，总共 O(n)。
- **空间复杂度**: O(1)。只使用常数个变量。

## 代码实现

```go
func MaxScore(cardPoints []int, k int) int {
    n := len(cardPoints)
    total := 0
    for _, p := range cardPoints {
        total += p
    }
    windowLen := n - k
    if windowLen == 0 {
        return total
    }
    // 初始窗口：前 windowLen 张牌
    sum := 0
    for i := 0; i < windowLen; i++ {
        sum += cardPoints[i]
    }
    minSum := sum
    // 滑动窗口，维护长度 windowLen 的连续子数组的最小和
    for right := windowLen; right < n; right++ {
        sum += cardPoints[right] - cardPoints[right-windowLen]
        if sum < minSum {
            minSum = sum
        }
    }
    return total - minSum
}
```

**执行过程示例**（示例 1：`cardPoints = [1,2,3,4,5,6,1], k = 3`）：

```
n = 7, windowLen = 7 - 3 = 4, total = 22
初始窗口 [1,2,3,4]: sum = 10, minSum = 10
滑到 [2,3,4,5]: sum = 14, minSum = 10
滑到 [3,4,5,6]: sum = 18, minSum = 10
滑到 [4,5,6,1]: sum = 16, minSum = 10
答案 = total - minSum = 22 - 10 = 12
```

> 观察：长度为 `n - k` 的「最小剩余段」被留下后，其余牌恰好构成一种合法的拿牌方案（从两头拿走）。本题点数均为正数时窗口越长总和越大，但求的是固定长度窗口的极值，与点数正负无关，该转化对任意整数点数组都成立。
