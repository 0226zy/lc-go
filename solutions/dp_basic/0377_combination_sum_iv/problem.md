# 0377. 组合总和 IV (Combination Sum IV)

## 题目描述

给你一个由**不同**整数组成的数组 `nums`，和一个目标整数 `target`。请你从 `nums` 中找出并返回总和为 `target` 的元素组合的个数。

题目数据保证答案符合 32 位整数范围。

**注意**：顺序不同的序列被视作不同的组合。例如 `(1, 1, 2)` 和 `(1, 2, 1)` 算两种组合，所以这道题实质上统计的是**排列数**。

### 示例

```
输入: nums = [1,2,3], target = 4
输出: 7
解释: 所有可能的组合为：
(1, 1, 1, 1)
(1, 1, 2)
(1, 2, 1)
(1, 3)
(2, 1, 1)
(2, 2)
(3, 1)
请注意，顺序不同的序列被视作不同的组合。
```

```
输入: nums = [9], target = 3
输出: 0
```

### 提示

- `1 <= nums.length <= 200`
- `1 <= nums[i] <= 1000`
- `nums` 中的所有元素**互不相同**
- `1 <= target <= 1000`

## 四步拆解

### 1. 状态定义

- `dp[i]` 表示**从 `nums` 中选数、总和恰好为 `i` 的排列（顺序敏感的组合）个数**。
- 最终答案：`dp[target]`。

为什么这样定义？凑出总和 `i` 的最后一个数必然是 `nums` 中的某个 `num`，在此之前需要凑出总和 `i - num`。大问题可以拆成「总和更小的同类问题」，一维数组足够描述全部状态。

### 2. 边界条件 + 遍历顺序

- base case：`dp[0] = 1`（「一个数都不选」是凑出总和 0 的唯一一种方式，它是所有累加的起点）。
- 遍历顺序：**外层正序遍历总和 `i` 从 1 到 `target`，内层遍历 `nums` 中的每个数**。`dp[i]` 依赖的 `dp[i-num]` 下标都比 `i` 小，正序保证它们先求好。

> **关键辨析**：这个「外层金额、内层物品」的顺序正是本题与 0518（零钱兑换 II）的本质区别。外层遍历金额时，对每个 `i` 都会尝试所有数作为「最后一个数」，`(1,2)` 和 `(2,1)` 会在不同的 `i-num` 来源里被各数一遍，因此统计的是**排列数**；而 0518 外层遍历硬币、内层金额，每种硬币按固定顺序逐批加入，只统计**组合数**。两题代码长得像，循环顺序绝不能互换。

### 3. 状态转移方程

```
dp[i] = Σ dp[i - num]   对所有满足 num <= i 的 num ∈ nums
```

推导：考虑凑出总和 `i` 的排列，看它的**最后一个数**是 `nums` 中的哪个 `num`（`num <= i`）。去掉这个最后的数，前面剩下的部分就是一个总和为 `i - num` 的排列，共有 `dp[i-num]` 种。不同的 `num` 对应互不重叠的排列集合，全部加起来就是 `dp[i]`。

边界特殊情况：`num > i` 时 `i - num` 为负，没有意义，直接跳过（`if num <= i` 判断）。

### 4. 样例验证 + 代码实现

手动推导 `nums = [1,2,3], target = 4`：

| i | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| dp[i] | 1 | 1 | 2 | 4 | 7 |

- `dp[1] = dp[0] = 1`（只有 [1]）
- `dp[2] = dp[1] + dp[0] = 1 + 1 = 2`（[1,1]、[2]）
- `dp[3] = dp[2] + dp[1] + dp[0] = 2 + 1 + 1 = 4`（[1,1,1]、[1,2]、[2,1]、[3]）
- `dp[4] = dp[3] + dp[2] + dp[1] = 4 + 2 + 1 = 7` ✅（与示例一致）

代码与上面的推导一一对应：

```go
// CombinationSum4 组合总和 IV（标准 DP 数组版）
func CombinationSum4(nums []int, target int) int {
	dp := make([]int, target+1)
	dp[0] = 1 // 一个数都不选，是凑出 0 的唯一方式
	for i := 1; i <= target; i++ {
		for _, num := range nums {
			if num <= i {
				// 最后一个数取 num：前面部分有 dp[i-num] 种排列
				dp[i] += dp[i-num]
			}
		}
	}
	return dp[target]
}
```

## 关于空间优化

本题**必须保留 DP 数组**，无法压缩成 O(1) 的滚动变量。原因是 `dp[i]` 依赖的 `dp[i-num]` 由 `nums` 中的元素决定：回看距离不是固定的常数（`nums` 里有多少种面额，就要同时回看多少个不同距离的历史值，最大距离可达 1000），不像爬楼梯那样只依赖固定的一两个前驱状态。任何时刻都可能用到 `dp[0..i-1]` 中的任意值，所以完整的一维数组 O(target) 空间就是本题的最优空间复杂度。

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| DP 数组版 | O(target × len(nums)) | O(target) |

**进阶**：如果 `nums` 元素很多、`target` 极大，可以用「生成函数 + 线性递推 + 矩阵快速幂」把对 `target` 的依赖降到对数级，但本题 `target <= 1000` 完全用不上。
