# 0518. 零钱兑换 II (Coin Change II)

## 题目描述

给你一个整数数组 `coins` 表示不同面额的硬币，另给一个整数 `amount` 表示总金额。

请你计算并返回可以凑成总金额的 **硬币组合数**。如果任何硬币组合都无法凑出总金额，返回 `0` 。

假设每一种面额的硬币有 **无限个**。

题目数据保证结果符合 32 位带符号整数。

### 示例

```
输入: amount = 5, coins = [1,2,5]
输出: 4
解释: 有四种方式可以凑成总金额:
5=5
5=2+2+1
5=2+1+1+1
5=1+1+1+1+1
```

```
输入: amount = 3, coins = [2]
输出: 0
解释: 只用面额 2 的硬币不能凑成总金额 3。
```

```
输入: amount = 10, coins = [10]
输出: 1
```

### 提示

- `1 <= coins.length <= 300`
- `1 <= coins[i] <= 5000`
- `coins` 中的所有值 **互不相同**
- `0 <= amount <= 5000`

## 四步拆解

### 1. 状态定义

- `dp[i][j]` 表示 **只使用前 `i` 种硬币，凑出金额 `j` 的组合数**。
- 最终答案：`dp[m][amount]`（`m = len(coins)`），即使用全部硬币种类凑出总金额的组合数。

这是一道典型的**完全背包计数**问题：每种硬币可以无限使用，问的是"方案数"而不是"最少硬币数"。计数类 DP 的套路是把所有互斥的选法对应的方案数**相加**。

### 2. 边界条件 + 遍历顺序

- base case：`dp[i][0] = 1`（`i = 0..m`）——凑出金额 0 只有一种组合：**一枚硬币都不选**。其余 `dp[0][j] = 0`（`j >= 1`）：没有硬币可用时凑不出任何正金额。
- 遍历顺序：**外层 `i` 从 1 到 m 正序（逐个考虑硬币种类），内层 `j` 从 1 到 amount 正序（金额从小到大）**。
  - `dp[i][j]` 依赖 `dp[i-1][j]`（上一行，先算完前 `i-1` 种硬币）和 `dp[i][j - coins[i-1]]`（同行左侧，金额更小），按此顺序遍历时两者都已算好。
  - 内层 `j` **必须正序**：`dp[i][j - coins[i-1]]` 是同一行里"已经允许使用第 `i` 种硬币"的结果，这正体现了"每种硬币可以重复选"（完全背包）；若倒序就变成每种只能选一次的 01 背包了。

### 3. 状态转移方程

```
dp[i][j] = dp[i-1][j]                          （不用第 i 种硬币）
         + dp[i][j - coins[i-1]]               （用至少一枚第 i 种硬币，仅当 j >= coins[i-1]）
```

推导：考虑第 `i` 种硬币（面额 `c = coins[i-1]`），凑金额 `j` 的组合可以分成互斥的两类——

- **完全不用第 `i` 种**：只用前 `i-1` 种硬币凑 `j`，共 `dp[i-1][j]` 种组合；
- **至少用一枚第 `i` 种**：先拿一枚面额 `c` 的硬币，剩下要凑的金额是 `j - c`，且仍然允许继续用第 `i` 种（无限供应），共 `dp[i][j - c]` 种组合。

两类互不重叠且穷尽所有组合，相加即可。边界特殊情况：`j < c` 时第二类不存在，只有 `dp[i][j] = dp[i-1][j]`。

### 4. 样例验证 + 代码实现

手动推导 `amount = 5, coins = [1,2,5]`：

| dp[i][j] | j=0 | j=1 | j=2 | j=3 | j=4 | j=5 |
| --- | --- | --- | --- | --- | --- | --- |
| i=0（无硬币） | 1 | 0 | 0 | 0 | 0 | 0 |
| i=1（面额 1） | 1 | 1 | 1 | 1 | 1 | 1 |
| i=2（面额 2） | 1 | 1 | 2 | 2 | 3 | 3 |
| i=3（面额 5） | 1 | 1 | 2 | 2 | 3 | 4 |

- `i=1` 行：只用面额 1，任何金额都只有"全用 1"一种组合；
- `dp[2][2] = dp[1][2] + dp[2][0] = 1 + 1 = 2`（`1+1`、`2`）；
- `dp[2][5] = dp[1][5] + dp[2][3] = 1 + 2 = 3`（`1×5`、`2+1+1+1`、`2+2+1`）；
- `dp[3][5] = dp[2][5] + dp[3][0] = 3 + 1 = 4` ✅（加入面额 5 后多了 `5=5` 这一种，与示例一致）。

代码与上面的推导一一对应：

```go
// Change 零钱兑换II（标准二维 DP 数组版）
func Change(amount int, coins []int) int {
	m := len(coins)
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, amount+1)
		dp[i][0] = 1 // base case：凑金额 0 只有「一枚都不选」一种组合
	}
	for i := 1; i <= m; i++ {
		c := coins[i-1]
		for j := 1; j <= amount; j++ {
			dp[i][j] = dp[i-1][j] // 不用第 i 种硬币
			if j >= c {
				dp[i][j] += dp[i][j-c] // 至少用一枚第 i 种硬币
			}
		}
	}
	return dp[m][amount]
}
```

## 空间优化版（仍使用一维 DP 数组）

观察转移方程：`dp[i][j]` 只依赖**上一行同一列**和**同一行左侧**，因此可以像完全背包的经典写法一样，把二维数组压成一维——`dp[j]` 滚动表示"使用到当前硬币种类时，凑金额 `j` 的组合数"：

```go
// ChangeOptimized 零钱兑换II（一维滚动数组空间优化版）
func ChangeOptimized(amount int, coins []int) int {
	dp := make([]int, amount+1)
	dp[0] = 1 // base case
	for _, c := range coins { // 硬币种类在外层：先固定种类再扫金额，保证组合不重复计数
		for j := c; j <= amount; j++ { // 金额正序：允许重复使用当前硬币（完全背包）
			dp[j] += dp[j-c]
		}
	}
	return dp[amount]
}
```

两点说明：

- **为什么外层必须是硬币、内层是金额**：本题求的是**组合数**（`2+2+1` 与 `2+1+2` 算同一种），硬币放外层保证每种硬币按顺序加入，不会因排列不同而重复计数；若金额放外层，求出来的就是排列数了。
- **为什么不能继续压到 O(1)**：每个金额 `j` 的方案数都依赖同一行中所有更小金额的累计值（`dp[j-c]`），这些历史值必须全部保留，空间最少需要 O(amount)，无法只用几个变量。

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| 二维 DP 数组版 | O(m × amount) | O(m × amount) |
| 一维滚动数组版 | O(m × amount) | O(amount) |
