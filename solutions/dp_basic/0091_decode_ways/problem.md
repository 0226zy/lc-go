# 0091. 解码方法 (Decode Ways)

## 题目描述

一条包含字母 `A-Z` 的消息通过以下映射进行了 **编码** ：

```
'A' -> "1"
'B' -> "2"
...
'Z' -> "26"
```

要 **解码** 已编码的消息，所有数字必须基于上述映射的方法，反向映射回字母（可能有多种方法）。例如，`"11106"` 可以映射为：

- `"AAJF"`，将消息分组为 `(1 1 10 6)`
- `"KJF"`，将消息分组为 `(11 10 6)`

注意，消息不能分组为 `(1 11 06)`，因为 `"06"` 不能映射为 `"F"`（`"6"` 和 `"06"` 不等价，数字不能以 0 开头）。

给你一个只含数字的 **非空** 字符串 `s`，请计算并返回 **解码** 方法的 **总数** 。

题目数据保证答案肯定是一个 **32 位** 的整数。

### 示例

```
输入: s = "12"
输出: 2
解释: 它可以解码为 "AB"（1 2）或者 "L"（12）。
```

```
输入: s = "226"
输出: 3
解释: 它可以解码为 "BZ" (2 26), "VF" (22 6), 或者 "BBF" (2 2 6)。
```

```
输入: s = "06"
输出: 0
解释: "06" 无法映射到 "F"，因为存在前导零。
```

### 提示

- `1 <= s.length <= 100`
- `s` 只包含数字，并且可能包含前导零。

## 四步拆解

### 1. 状态定义

- `dp[i]` 表示**字符串前 `i` 个字符（即 `s[:i]`）的解码方法总数**。
- 最终答案：`dp[n]`（n 为字符串长度），即整个字符串的解码方法数。

为什么这样定义？解码最后一个字母时，要么只消耗最后 **1** 个数字（剩下前 i-1 个字符随便解码），要么消耗最后 **2** 个数字（剩下前 i-2 个字符随便解码）。两种分组的「剩余部分」都是更短前缀的解码问题，一维数组就足够描述全部状态。

### 2. 边界条件 + 遍历顺序

- base case：
  - `dp[0] = 1`：空串算 1 种「解码方式」。它不是真实答案，而是转移的基石——比如 `"12"` 整体作为 "12" 解码时，需要加上 `dp[0]`。
- 遍历顺序：**i 从 1 到 n 正序遍历**。`dp[i]` 只依赖 `dp[i-1]` 和 `dp[i-2]`，都是下标更小的子问题，正序保证它们先求好。

### 3. 状态转移方程

考虑最后一个字母怎么解码（注意 `dp[i]` 对应的前缀末尾字符是 `s[i-1]`）：

```
dp[i] = 0
如果 s[i-1] != '0':                       // 最后一个数字单独解码
    dp[i] += dp[i-1]
如果 i >= 2 且 10 <= s[i-2..i-1] <= 26:   // 最后两个数字合并解码
    dp[i] += dp[i-2]
```

推导：解码到第 `i` 个字符为止，最后一组的切法只有两种——

- **单独切出 `s[i-1]`**：前提是它不为 `'0'`（"0" 无法映射任何字母），此时前 i-1 个字符有 `dp[i-1]` 种解码；
- **把 `s[i-2]s[i-1]` 两个数字一起切出**：前提是组成的两位数在 10~26 之间（小于 10 说明有前导零，大于 26 超出 'Z'），此时前 i-2 个字符有 `dp[i-2]` 种解码。

两种切法互斥且穷尽，加起来就是 `dp[i]`。若两个前提都不满足（比如 `"30"` 中的 `'0'` 前是 `'3'`），`dp[i] = 0`，表示该前缀根本无法解码，后续状态也会被传导为 0。

边界特殊情况：`i = 1` 时只有两个数字合并的前置条件 `i >= 2` 不满足，只看单数字即可；前导零、`'0'` 出现在十位等非法情况都被上面的前提条件自然过滤。

### 4. 样例验证 + 代码实现

手动推导 `s = "226"`：

| i | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 前缀 | "" | "2" | "22" | "226" |
| dp[i] | 1 | 1 | 2 | **3** |

- `dp[1]`：'2' ≠ '0'，`dp[1] = dp[0] = 1`
- `dp[2]`：'2' ≠ '0' 加 `dp[1]=1`；"22" ∈ [10,26] 加 `dp[0]=1` → `dp[2] = 2`
- `dp[3]`：'6' ≠ '0' 加 `dp[2]=2`；"26" ∈ [10,26] 加 `dp[1]=1` → `dp[3] = 3` ✅（与示例一致）

再看 `s = "06"`：`dp[1]` 时 `'0'` 不能单独解码，`dp[1] = 0`；`dp[2]` 时 '6' 可加 `dp[1]=0`，"06" = 6 < 10 不能合并，`dp[2] = 0` ✅。

代码与上面的推导一一对应：

```go
// NumDecodings 解码方法（标准 DP 数组版）
func NumDecodings(s string) int {
	n := len(s)
	dp := make([]int, n+1)
	dp[0] = 1 // 空串视为一种解码，作为转移基石
	for i := 1; i <= n; i++ {
		if s[i-1] != '0' {
			dp[i] += dp[i-1] // 最后一个数字单独解码
		}
		if i >= 2 {
			two := int(s[i-2]-'0')*10 + int(s[i-1]-'0')
			if two >= 10 && two <= 26 {
				dp[i] += dp[i-2] // 最后两个数字合并解码
			}
		}
	}
	return dp[n]
}
```

## 空间优化版（不使用 DP 数组）

观察转移方程：`dp[i]` 只依赖 `dp[i-1]` 和 `dp[i-2]`，更早的状态再也不会用到。这与爬楼梯 / 斐波那契的结构完全一样，只需两个滚动变量 `prev2`（代表 `dp[i-2]`）、`prev1`（代表 `dp[i-1]`）迭代即可，空间从 O(n) 降到 O(1)：

```go
// NumDecodingsOptimized 解码方法（滚动变量空间优化版）
func NumDecodingsOptimized(s string) int {
	n := len(s)
	if s[0] == '0' {
		return 0 // 前导零无法解码
	}
	prev2, prev1 := 1, 1 // 分别代表 dp[0]、dp[1]
	for i := 2; i <= n; i++ {
		cur := 0
		if s[i-1] != '0' {
			cur += prev1 // 最后一个数字单独解码
		}
		two := int(s[i-2]-'0')*10 + int(s[i-1]-'0')
		if two >= 10 && two <= 26 {
			cur += prev2 // 最后两个数字合并解码
		}
		prev2, prev1 = prev1, cur
	}
	return prev1
}
```

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| DP 数组版 | O(n) | O(n) |
| 滚动变量版 | O(n) | O(1) |
