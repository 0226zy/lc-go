# 0055. 跳跃游戏 (Jump Game)

## 题目描述

给你一个非负整数数组 `nums`，你最初位于数组的**第一个下标**。数组中的每个元素代表你在该位置可以跳跃的**最大长度**（从下标 `i` 可以跳到任意 `i + j`，其中 `0 <= j <= nums[i]`）。

判断你是否能够到达**最后一个下标**，如果可以，返回 `true`；否则，返回 `false`。

### 示例

```
输入: nums = [2,3,1,1,4]
输出: true
解释: 可以先跳 1 步，从下标 0 到达下标 1，然后再从下标 1 跳 3 步到达最后一个下标。
```

```
输入: nums = [3,2,1,0,4]
输出: false
解释: 无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0，
     所以永远不可能到达最后一个下标。
```

### 提示

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`

## 四步拆解

### 1. 状态定义

- `dp[i]` 表示**下标 `i` 是否可达**，布尔类型。
- 最终答案：`dp[n-1]`。

### 2. 边界条件 + 遍历顺序

- base case：`dp[0] = true`（起点本来就在脚下）。
- 遍历顺序：**正序从 1 到 n-1**。`dp[i]` 依赖所有能一步跳到 `i` 的前驱位置 `j`（`j < i`），这些子问题下标更小，正序保证先求解。

### 3. 状态转移方程

```
dp[i] = 存在某个 j (0 <= j < i)，使得 dp[j] == true 且 j + nums[j] >= i
```

推导：考虑第 `i` 个位置能不能到——只要存在**任意一个**可达的前驱 `j`，且它的最大跳跃距离能覆盖到 `i`（`j + nums[j] >= i`），那么 `i` 就可达。只要找到一个这样的前驱就可以提前结束内层循环（`break`），属于「或」关系的转移。

### 4. 样例验证 + 代码实现

手动推导 `nums = [3,2,1,0,4]`：

| i | nums[i] | 是否存在可行前驱 | dp[i] |
| --- | --- | --- | --- |
| 0 | 3 | —（起点） | true |
| 1 | 2 | 0+3>=1 ✅ | true |
| 2 | 1 | 0+3>=2 ✅ | true |
| 3 | 0 | 0+3>=3 ✅ | true |
| 4 | 4 | 3+0=3<4，其余前驱也都不够 ❌ | false |

`dp[4] = false` ✅（与示例一致）

代码与上面的推导一一对应：

```go
// CanJump 跳跃游戏（标准 DP 数组版）
func CanJump(nums []int) bool {
	n := len(nums)
	dp := make([]bool, n)
	dp[0] = true
	for i := 1; i < n; i++ {
		for j := 0; j < i; j++ {
			if dp[j] && j+nums[j] >= i { // 前驱 j 可达且能跳到 i
				dp[i] = true
				break
			}
		}
	}
	return dp[n-1]
}
```

## 贪心版（不使用 DP 数组）

DP 版是 O(n²)。换个角度：这道题不需要真的去模拟"每一步跳到哪里"，因为跳跃可长可短，选择太多，模拟会演变成指数级搜索。我们只关心一件事：**当前最远能到达哪里**。

维护一个变量 `farthest` 表示"从起点出发，经过若干次跳跃，最远能够到达的下标"。正序遍历每个位置 `i`：

- 如果 `i > farthest`，说明这个位置本身都到不了，后面更不可能，直接返回 `false`；
- 否则用 `i + nums[i]` 更新 `farthest`。一旦 `farthest >= n-1`，说明终点可达，返回 `true`。

贪心成立的原因：跳跃长度是"最多跳 `nums[i]`"，站在 `i` 时可以落在 `i+1` 到 `i+nums[i]` 的**任意**位置——既然每个中间位置都能自由到达，那么"最远能到哪里"这一个信息就足以概括所有可能，不需要记录具体路径。本题属于**「贪心维护最右可达边界」**的经典模型。

```go
// CanJumpAlternative 跳跃游戏（贪心版）
func CanJumpAlternative(nums []int) bool {
	farthest := 0
	for i := 0; i < len(nums); i++ {
		if i > farthest { // 当前位置不可达，后面更不可能
			return false
		}
		farthest = max(farthest, i+nums[i])
		if farthest >= len(nums)-1 { // 已能覆盖终点
			return true
		}
	}
	return true
}
```

贪心版执行过程示例（`nums = [3,2,1,0,4]`）：

```
初始: farthest=0
i=0: nums[0]=3，farthest = max(0, 0+3) = 3
i=1: nums[1]=2，farthest = max(3, 1+2) = 3
i=2: nums[2]=1，farthest = max(3, 2+1) = 3
i=3: nums[3]=0，farthest = max(3, 3+0) = 3
i=4: i=4 > farthest=3，说明下标 4 不可达，返回 false
```

> 说明：在「面试经典 150 题」官方分类中，本题的"标准解法"其实是**贪心**而非 DP——上面 DP 数组版是理解状态的切入点，贪心版才是时间最优的推荐写法，这也解释了为什么本题被归入贪心类题目。

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| DP 数组版 | O(n²) | O(n) |
| 贪心版 | O(n) | O(1) |
