# 162. 寻找峰值 (Find Peak Element)

## 题目描述

峰值元素是指其值**严格大于**左右相邻值的元素。

给你一个整数数组 `nums`，找到峰值元素并返回其索引。数组可能包含多个峰值，在这种情况下，返回**任何一个峰值**所在位置即可。

你可以假设 `nums[-1] = nums[n] = -∞`。

你必须实现时间复杂度为 `O(log n)` 的算法来解决此问题。

### 示例 1

```
输入: nums = [1,2,3,1]
输出: 2
解释: 3 是峰值元素，你的函数应该返回其索引 2。
```

### 示例 2

```
输入: nums = [1,2,1,3,5,6,4]
输出: 1 或 6
解释: 你的函数可以返回索引 1，其峰值元素为 2；
     或者返回索引 5，其峰值元素为 6。
```

## 提示

- `1 <= nums.length <= 1000`
- `-2^31 <= nums[i] <= 2^31 - 1`
- 对于所有有效的 `i` 都有 `nums[i] != nums[i + 1`

## 题目解析

### 核心思路

第一眼会觉得峰值是“随机出现”的，只能线性扫描，但注意题目假设了边界是 `-∞`，再加上**相邻元素互不相等**的条件，就有了二分的依据：

**只要沿着“上坡”方向走，就一定能到达一个峰值。** 想象你在一个山坡上，只要脚下是往上的（`nums[mid] < nums[mid+1]`），就继续往右走，右边要么还是上坡要么到了山顶；如果脚下是往下的，山顶就在左边（含自己）。

为什么一定存在峰值？这是离散版的“上山必有顶”：数组相邻元素不等，从任意点沿递增方向前进，序列严格递增。严格递增又不能无限延伸（数组有界），且右边界外是 `-∞`，所以必在某处由增转降，该转折点就是峰值。

因此二分判断只需看**右边邻居**：

- `nums[mid] < nums[mid+1]`：处于上坡，峰值在右半边，`left = mid + 1`
- `nums[mid] > nums[mid+1]`：mid 本身是下坡的起点，峰值在左半边（含 mid），`right = mid`

### 算法步骤

1. 初始化 `left, right = 0, len(nums)-1`
2. 当 `left < right`：
   - `mid = (left + right) / 2`
   - 若 `nums[mid] < nums[mid+1]`，`left = mid + 1`（去右边上坡）
   - 否则 `right = mid`（mid 可能就是峰值或其左侧有峰值）
3. 返回 `left`（收敛处即为峰值）

### 复杂度分析

- **时间复杂度**: O(log n)，二分查找
- **空间复杂度**: O(1)，常数变量

## 代码实现

```go
func FindPeakElement(nums []int) int {
    left, right := 0, len(nums)-1
    for left < right {
        mid := (left + right) / 2
        if nums[mid] < nums[mid+1] {
            left = mid + 1 // 处于上坡，峰值在右侧
        } else {
            right = mid // mid 本身就是下坡起点，峰值在左侧（含 mid）
        }
    }
    return left
}
```

**执行过程示例**（`nums = [1,2,1,3,5,6,4]`）：

```
left=0, right=6
mid=2: nums[2]=1 < nums[3]=3, 处于上坡, left=3
mid=4: nums[4]=5 < nums[5]=6, 处于上坡, left=5
mid=5: nums[5]=6 > nums[6]=4, 下坡起点, right=5
left == right == 5, 返回 5（值 6 是峰值）
```
