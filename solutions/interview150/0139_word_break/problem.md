# 0139. 单词拆分 (Word Break)

## 题目描述

给你一个字符串 `s` 和一个字符串列表 `wordDict` 作为字典。如果可以利用字典中出现的一个或多个单词拼接出 `s`，则返回 `true`。

**注意**：不要求字典中出现的单词全部都使用，并且字典中的单词可以重复使用。

### 示例

```
输入: s = "leetcode", wordDict = ["leet", "code"]
输出: true
解释: 返回 true，因为 "leetcode" 可以由 "leet" 和 "code" 拼接成。
```

```
输入: s = "applepenapple", wordDict = ["apple", "pen"]
输出: true
解释: 返回 true，因为 "applepenapple" 可以由 "apple" "pen" "apple" 拼接成。
     注意可以重复使用字典中的单词。
```

```
输入: s = "catsandog", wordDict = ["cats", "dog", "sand", "and", "cat"]
输出: false
```

### 提示

- `1 <= s.length <= 300`
- `1 <= wordDict.length <= 1000`
- `1 <= wordDict[i].length <= 20`
- `s` 和 `wordDict[i]` 仅由小写英文字母组成
- `wordDict` 中的所有字符串互不相同

## 四步拆解

### 1. 状态定义

- `dp[i]` 表示字符串的**前 `i` 个字符**（即前缀 `s[:i]`）能否用字典中的单词拼接出来。
- 最终答案：`dp[n]`（`n` 为 `s` 的长度），即整个字符串能否被完整拆分。

为什么按前缀定义？因为拼接是有顺序的：如果前 `j` 个字符可以拼出来，且剩下的 `s[j:i]` 恰好是字典里的一个单词，那么前 `i` 个字符也一定能拼出来。问题被拆成了规模更小的同类子问题。

### 2. 边界条件 + 遍历顺序

- base case：`dp[0] = true`。空字符串不需要任何单词就能「拼」出来，它是所有拼接的起点；如果把它设为 `false`，后面任何状态都推不出来。
- 遍历顺序：**外层 `i` 从 1 到 n 正序，内层 `j` 从 0 到 i-1 正序**。`dp[i]` 依赖所有 `dp[j]`（`j < i`），外层正序保证算 `dp[i]` 时它依赖的所有更短前缀都已经求好。

### 3. 状态转移方程

```
dp[i] = 存在某个 j (0 <= j < i)，使得 dp[j] == true 且 s[j:i] 在字典中
```

推导：考虑前 `i` 个字符的**最后一个单词**是什么。设它从下标 `j` 开始（即 `s[j:i]`），那么只要满足两个条件，前 `i` 个字符就能拼出来：

1. 前面的 `s[:j]` 能拼出来（`dp[j] == true`）；
2. 最后一段 `s[j:i]` 本身是字典里的单词。

只要存在**任意一个**这样的 `j`，`dp[i]` 就是 `true`；枚举完所有 `j` 都不行，则为 `false`。边界特殊情况：`dp[0] = true` 保证了「整个前缀本身就是一个单词」时（`j = 0`）也能正确转移。

实现上先把 `wordDict` 放进一个 `map[string]bool`，让「`s[j:i]` 是否在字典中」的查询变成 O(1)（不计子串截取开销）。

### 4. 样例验证 + 代码实现

手动推导 `s = "leetcode"`，`wordDict = ["leet", "code"]`：

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 前缀 | "" | l | le | lee | leet | leetc | leetco | leetcod | leetcode |
| dp[i] | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ | ❌ | ✅ |

- `dp[1..3]`：`"l"`、`"le"`、`"lee"` 都不在字典中 → `false`。
- `dp[4]`：`j = 0`，`dp[0] = true` 且 `s[0:4] = "leet"` 在字典中 → `true`。
- `dp[8]`：`j = 4`，`dp[4] = true` 且 `s[4:8] = "code"` 在字典中 → `true` ✅（与示例一致）。

再看反例 `s = "catsandog"`：虽然 `"cats"`、`"sand"`、`"and"` 等片段都在字典里，但从 `dp[0]` 出发走不到 `dp[9]`——比如想以 `"dog"` 结尾，需要 `dp[6]`（`"catsan"`）为 `true`，而它并不成立，其余切法同理全部走不通，所以最终为 `false`。

代码与上面的推导一一对应：

```go
// WordBreak 单词拆分（标准 DP 数组版）
func WordBreak(s string, wordDict []string) bool {
	n := len(s)
	wordSet := make(map[string]bool, len(wordDict))
	for _, w := range wordDict {
		wordSet[w] = true
	}
	dp := make([]bool, n+1)
	dp[0] = true // base case：空前缀
	for i := 1; i <= n; i++ {
		for j := 0; j < i; j++ {
			if dp[j] && wordSet[s[j:i]] {
				dp[i] = true
				break // 找到一种拼法即可
			}
		}
	}
	return dp[n]
}
```

## 为什么不用「空间优化版」

本题**无法**像爬楼梯那样压缩成 O(1) 空间：`dp[i]` 依赖的是 `dp[0]` 到 `dp[i-1]` 中的**任意一个**（最后那个单词可以从任意位置开始），而不是固定的前几个状态，所以整个 `dp` 数组都必须保留。这属于「前缀型 DP」的固有特点，类似的还有 0518 零钱兑换 II 等，数组形态就是它们最自然的写法。

另一个可选方向是「DFS + 记忆化搜索」，自顶向下枚举拆分点，时间和空间复杂度与 DP 相同（O(n²) / O(n)），本质是同一件事换了种写法，这里不再单列。

## 复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| DP 数组版 | O(n²)（不计子串哈希开销） | O(n + 字典总字符数) |

`n = len(s)`：外层枚举 `i`、内层枚举 `j` 共 O(n²) 次检查，字典预处理为 O(字典总字符数)。

**进阶**：字典单词最长为 `maxLen`（提示中不超过 20），所以 `s[j:i]` 长度超过 `maxLen` 时必然不在字典里，内层 `j` 只需从 `i - maxLen` 开始枚举（不小于 0），可以把内层枚举范围从 O(n) 降到 O(maxLen)。本题属于「一维线性 DP / 完全背包判定」模板——把字符串长度看作背包容量、字典单词看作可无限选取的物品，核心是「枚举最后一段，查表验证」。
