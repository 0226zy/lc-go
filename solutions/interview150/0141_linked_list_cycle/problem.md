# 141. 环形链表 (Linked List Cycle)

## 题目描述

给你一个链表的头节点 `head` ，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达该节点，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（**索引从 0 开始**）。**注意：`pos` 不作为参数进行传递**，它仅仅是为了说明链表中存在环。

**不允许修改** 链表。

### 示例 1

```
输入: head = [3,2,0,-4], pos = 1
输出: true
解释: 链表中有一个环，其尾部连接到第二个节点。
```

### 示例 2

```
输入: head = [1,2], pos = 0
输出: true
解释: 链表中有一个环，其尾部连接到第一个节点。
```

### 示例 3

```
输入: head = [1], pos = -1
输出: false
解释: 链表中没有环。
```

## 提示

- 链表中节点的数目范围是 `[0, 10^4]`
- `-10^5 <= Node.val <= 10^5`
- `pos` 为 `-1` 或者链表中的一个 **有效索引**

## 题目解析

### 核心思路

这是典型的「**Floyd 判圈算法（快慢指针）**」模板题，也叫龟兔赛跑算法。

想象一个环形跑道上两个人跑步：一个人跑得快（每次走两步），一个人跑得慢（每次走一步）。如果跑道是直的（无环），快的人会先到终点，两人永远不会再相遇；如果跑道是环形的（有环），快的人迟早会绕圈追上慢的人——这就是本题的直觉。

**为什么有环一定会相遇？** 进入环后，快指针每次比慢指针多走 1 步，相当于每轮把两者的距离缩小 1。即使快指针本来在慢指针前面，两人的距离（沿环计算）也会从 `d` 一步步缩小到 `0`，所以一定相遇。

**为什么无环一定不相遇？** 无环时快指针会先走到 `nil`（快指针一次走两步，若快指针的 `Next` 或 `Next.Next` 为 `nil`，循环结束），不可能与慢指针相遇。

另一种思路是用哈希集合记录访问过的节点，重复访问说明有环，但空间复杂度是 O(n)，不如快慢指针的 O(1) 空间。

### 算法步骤（快慢指针）

1. 初始化两个指针 `slow` 和 `fast` 都指向 `head`
2. 循环：只要 `fast` 和 `fast.Next` 都不是 `nil`：
   - `slow` 前进一步：`slow = slow.Next`
   - `fast` 前进两步：`fast = fast.Next.Next`
   - 如果 `slow == fast`（指针相同即相遇），返回 `true`
3. 循环结束（`fast` 到达链表末尾）返回 `false`

### 复杂度分析

- **时间复杂度**: O(n)。无环时快指针走完全程 O(n)；有环时，设环外长度为 a、环长为 c，相遇前最多走 a + c 步，仍是 O(n)
- **空间复杂度**: O(1)。只使用两个指针，无额外数据结构

## 代码实现

### 快慢指针（Floyd 判圈）

```go
func hasCycle(head *datastructures.ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next      // 慢指针走一步
        fast = fast.Next.Next // 快指针走两步
        if slow == fast {     // 相遇说明有环
            return true
        }
    }
    return false // 快指针到末尾，无环
}
```

**执行过程示例**（`head = [3,2,0,-4], pos = 1`，环为 2 → 0 → -4 → 2）：

```
初始: slow=3, fast=3
第1轮: slow=2, fast=0      （fast 走两步: 3→2→0）
第2轮: slow=0, fast=2      （fast 走两步: 0→-4→2）
第3轮: slow=-4, fast=-4    （fast 走两步: 2→0→-4）
       slow == fast，相遇！返回 true
```
