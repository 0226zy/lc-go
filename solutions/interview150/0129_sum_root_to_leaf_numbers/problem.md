# 129. 求根节点到叶节点数字之和 (Sum Root to Leaf Numbers)

## 题目描述

给你一个二叉树的根节点 `root`，树中每个节点都存放有一个 `0` 到 `9` 之间的数字。

每条从根节点到叶节点的路径都代表一个数字：

- 例如，路径 `1 -> 2 -> 3` 表示数字 `123`。

计算从根节点到所有叶节点路径所代表的所有数字之和。

### 示例 1

```
输入: root = [1,2,3]
输出: 25
解释:
从根到叶的路径 1 -> 2 代表数字 12
从根到叶的路径 1 -> 3 代表数字 13
总和 = 12 + 13 = 25
```

### 示例 2

```
输入: root = [4,9,0,5,1]
输出: 1026
解释:
从根到叶的路径 4 -> 9 -> 5 代表数字 495
从根到叶的路径 4 -> 9 -> 1 代表数字 491
从根到叶的路径 4 -> 0 代表数字 40
总和 = 495 + 491 + 40 = 1026
```

### 提示

- 树中节点数的范围是 `[1, 1000]`
- `Node.val` 只包含数字 `0 ~ 9`
- 树的深度不会超过 `10`

## 题目解析

### 核心思路

也是**「自上而下传递状态」的 DFS 模板**，与路径总和（112）是同一个模型：递归向下走时维护一个「从根到当前节点的路径数字」，每深入一层就把这个数字**左移一位**（乘 10）再加上当前节点值。

到达叶节点时，这条路径的数字就完整了，直接把它累加进答案；内部节点则把左右子树的累加结果相加。不需要任何全局变量，递归的返回值天然完成了求和。

一个容易写错的地方：空节点要返回 `0`（它不构成任何路径），但**不能**用「空节点返回 0」来判断叶节点——叶节点的判定必须放在空检查之后、且要求左右都为空，否则单孩子节点的缺失一边会被误当成一条「路径」。

### 算法步骤

定义递归函数 `dfs(node, acc)`，表示「从根走到 `node`，路径数字已累计为 `acc`，返回 `node` 子树中所有根到叶路径数字之和」：

1. 若 `node` 为空，返回 `0`。
2. 更新 `acc = acc * 10 + node.Val`。
3. 若 `node` 是叶节点，返回 `acc`（这条路径的数字到此为止）。
4. 否则返回 `dfs(node.Left, acc) + dfs(node.Right, acc)`。

主函数返回 `dfs(root, 0)`。

### 复杂度分析

- **时间复杂度**: O(n)，每个节点恰好访问一次
- **空间复杂度**: O(h)，递归栈深度，h 为树高；最坏（链状树）为 O(n)。注意树深不超过 10，所以 int 不会溢出

## 代码实现

```go
func SumNumbers(root *TreeNode) int {
	var dfs func(node *TreeNode, acc int) int
	dfs = func(node *TreeNode, acc int) int {
		if node == nil {
			return 0
		}
		// 路径数字整体左移一位，加上当前位
		acc = acc*10 + node.Val
		// 叶节点：这条路径的数字已完整
		if node.Left == nil && node.Right == nil {
			return acc
		}
		// 内部节点：累加左右子树各自形成的数字之和
		return dfs(node.Left, acc) + dfs(node.Right, acc)
	}
	return dfs(root, 0)
}
```

**执行过程示例**（示例 2，`root = [4,9,0,5,1]`）：

```
dfs(4, 0)    acc = 4
 ├─ dfs(9, 4)   acc = 49
 │   ├─ dfs(5, 49)  → 叶节点，返回 495
 │   └─ dfs(1, 49)  → 叶节点，返回 491
 │   小计: 495 + 491 = 986
 └─ dfs(0, 4)   acc = 40 → 叶节点，返回 40
总计: 986 + 40 = 1026
```
